# ゆらぎの全体設計（TIP・ブローカー・エンジン、置き場所、インストール）

ゆらぎを構成するプロセス、その間の通信、ファイルの置き場所、インストールの手順、利用者に見えるものの仕様。
コードのコメントは、この文書の節を名前で参照する（DESIGN「見張り」など）。数値は「定数」の表にまとめ、
本文は名前で書く。変換の中身（打鍵の判定、変換、候補、学習）は [CONVERSION.md](CONVERSION.md)。

利用者に見える動きで迷ったときは、MS-IME（新 MS-IME を実機で見た動き）に合わせることを目安にする。
ゆらぎ独自なのは、親指シフトの入力（文字キーと Space の同時打鍵、文字の面）。MS-IME の動きは [keybind/ms-ime.md](keybind/ms-ime.md) にまとめ、
そこに無い動きは、作る前に実機で確かめる。

## 1. 構成

```
アプリ ──[TIP DLL]──(名前付きパイプ)──[ブローカー]──(標準入出力)──[変換エンジン]
          薄い・状態が少ない          小さい・ネイティブ        大きい・Python
          アプリの中で動く            落ちない前提で作る        落ちることを前提に扱う
```

| 部品 | 実体 | 数 | 誰が起動するか | 役目 |
|---|---|---|---|---|
| TIP | `yuragi_tip.dll`（C++。32 ビットのアプリには `yuragi_tip32.dll`） | アプリのスレッドごと | Windows | 打鍵を送り、返事を画面に書く。プロセス管理・再試行は持たない。読むファイルは `tip.json` だけで、書くのは頼まれたときのログだけ |
| ブローカー | `yuragi-broker.exe`（C++、ウィンドウなし） | サインインごとに 1 | サインイン時（Run キー）。無ければ TIP が条件付きで | エンジンを起動し、見張り、落ちたら起動し直す。打鍵と返事を配る |
| エンジン | 同梱 Python で `yuragi.engine`（下の注） | ブローカーごとに 1 | ブローカーだけ | 辞書・学習・LM を抱えて変換する |
| 設定ウィンドウ | 同梱の `pythonw` で `yuragi.ime.admin_ui` | 利用者が開いたとき | ブローカー（TIP のメニューから依頼） | 単語登録・学習・設定・キー・状態 |

注: 同梱の Python は埋め込み版で、`-m` では作業フォルダからモジュールを探さない。`engine.json` の `args`・`admin_args` は、`-c` の前置き（作業フォルダを `sys.path` に入れて `runpy` する）でモジュールを動かす（`packaging/setup.ps1`）。

### 守ること

| # | 守ること |
|---|---|
| 1 | **打った文字は消えない。** エンジンに何が起きても、画面に出ていた文字はそのまま確定する（「見えている文字の確定」） |
| 2 | **エンジンが落ちても数秒の間で済む。** 起動し直しを決めるのはブローカーだけ。`ENGINE_EXIT_WINDOW_MS` の間に `ENGINE_MAX_EXITS` 回落ちたら止まり、利用者の操作かサインインまで再開しない |
| 3 | **直らない故障は、1 回だけ普通の言葉で知らせる。** 「もう一度試す」がそこにある |
| 4 | **勝手にウィンドウを出さない。フォーカスを奪わない。** 現れるウィンドウは利用者が開いたものだけ。どのプロセスもコンソールなしで起動する |
| 5 | **PC に掛ける負荷に上限がある。** TIP が打鍵 1 回（Windows からの呼び出し 1 回）で UI スレッドを止めるのは、その中の書き込みと返事待ちを合わせて `KEY_BUDGET_MS` まで。TIP が接続（ブローカーの起動を含む）を試す間隔は、利用者の操作によるときを除いて `CONNECT_MIN_INTERVAL_MS` 以上（「接続」）。入力の長さ（`MAX_TOKENS`）にも上限がある。TIP のログ（`tip.json` の `log`）は調べるときだけ有効にするもので、上限を設けない |
| 6 | **インストール・更新・アンインストールは、アプリを閉じなくても終わる。** |
| 7 | **利用者のデータ（学習履歴・個人辞書・設定）を、頼まれずに消さない。** |

## 2. 置き場所

```
%ProgramFiles%\yuragi-ime\<tag>\          管理者だけが書ける。全アプリに読み込まれるものはここ
    yuragi_tip.dll  yuragi_tip32.dll  yuragi-broker.exe  elevated.ps1

%LOCALAPPDATA%\yuragi-ime\                 利用者の権限で動くものだけ。管理者権限では決して実行しない
    versions\<tag>\app\                     Python のソース
    versions\<tag>\engine.json              このタグが使う共有物への道順（ブローカーが読む。形は src/broker/support.h）
    shared\runtime\<id>\                    同梱 Python + tkinter + torch + 依存。id = 版とハッシュ
    shared\dict\<id>\                       Mozc 辞書
    shared\cache\<id>.pkl                   辞書キャッシュ
    shared\model\<リビジョン>\              LM モデル
    staging\                                更新の作業場。成功したら versions へ移す

%USERPROFILE%\.yuragi-ime\                 利用者のデータ。更新でもアンインストールでも触らない
    config.json  tip.json  keymap.json
    learning.jsonl  learning.jsonl.lock  personal_lexicon.jsonl
    logs\broker.log  logs\engine.log  logs\notices.log（それぞれ前の世代 *.prev.log）

HKLM  CLSID → %ProgramFiles%\yuragi-ime\<tag>\yuragi_tip.dll（32 ビット側の CLSID は yuragi_tip32.dll）、TIP 登録（共通）
HKCU\Software\yuragi-ime   Tag = <tag>     「この利用者には、この版が入っている」の唯一の印
HKCU\…\CurrentVersion\Run   yuragi-ime = "…\<tag>\yuragi-broker.exe"
```

- **版ごとにフォルダを分ける。** 更新は「新しいフォルダを作って、登録を付け替える」だけで、
  読み込まれている DLL には触らない。だからアプリを開いたまま更新できる。
- **ランタイム・辞書・モデルは共有する。** ランタイムは Python の版、torch の版と種類、
  `requirements.txt` のハッシュで、モデルはリビジョンで名前を付ける。
  同じ名前のフォルダがあれば再利用する。
  ランタイムに入るものは pip 自体を除き、版とハッシュを固定している（「共通の仕組み」）。
- **学習履歴と個人辞書はプログラムのフォルダの外**に置く。
- **Python は同梱ランタイム 1 本。** ほかの Python を探さない。

## 3. 通信

### TIP とブローカー（名前付きパイプ）

- 名前: `\\.\pipe\yuragi-ime-<利用者の SID>-<セッション番号>`。バイト単位、1 行 1 JSON（UTF-8、`\n` 区切り）。
- アクセス権: その利用者に読み書き。加えて「すべてのアプリパッケージ」（`S-1-15-2-1`）に読み書き
  ——スタートメニューの検索欄など、サンドボックス内のアプリからも**接続だけは**できるようにする。
  アプリパッケージからの接続（相手のプロセスのトークンの `TokenIsAppContainer` で見る。調べられなければ
  アプリパッケージとみなす）は TIP として扱い、TIP が送るもの（hello・打鍵・`retry`・`open_admin`）だけを受け付ける。
  `quit` は無視する。
  接続できないアプリでは、そこでは素通しになる。他の利用者・ネットワークからは不可（`PIPE_REJECT_REMOTE_CLIENTS`）。
- TCP・ポート番号・トークンは使わない。パイプが在ること自体が「ブローカーがいる」の印になる。
- ブローカーのいない間に別のプロセスが同じ名前のパイプを先に作れるので、TIP はつないだ相手を確かめる。
  相手のプロセス（`GetNamedPipeServerProcessId`）の実行ファイルが、この DLL と同じフォルダか、その隣の版のフォルダ
  （更新のあと開いたままのアプリの旧 DLL が新しいブローカーにつなぐ）の `yuragi-broker.exe` でなければ、
  あるいはそれを調べられなければ、切って対象外にする。相手が TIP になりすませないよう、偽装は識別まで（`SECURITY_IDENTIFICATION`）。
  アプリコンテナーの中のアプリ（UWP、スタートメニューの検索欄など）は、相手のプロセスを開けない（`OpenProcess` が拒否される）。
  そのときは、パイプを作った者を見る: パイプの所有者がこの利用者で、整合性レベルが中以上（ラベルが無ければ中）なら受け入れる。
  同じ利用者でも、整合性レベルが低のプロセスが作ったパイプには低のラベルが付き、アプリコンテナーはこの名前のパイプを作れない。

TIP → ブローカー（プロトコル 1）:

```json
{"op":"hello","proto":1}
{"seq":17,"op":"down","vk":74,"t":123456,"mods":[]}        ← op は down/up/timeout/reset/set_direct/set_mode/suggest/reload_keymap
{"op":"retry"}                                              ← 利用者が「もう一度試す」を選んだ
{"op":"open_admin"}                                         ← 設定ウィンドウを開く（最初のタブの単語登録で開く）
{"op":"quit"}                                               ← インストーラだけが使う（アプリパッケージからは受け付けない）
```

ブローカー → TIP:

```json
{"proto":1,"state":"ready","warnings":[],"keymap":{…}}      ← hello の返事。keymap はブローカーが持つ最新の食べる表（無ければ項目ごと無い）
{"seq":17, …エンジンの返事の全項目… }                      ← 要求の返事（エンジンの返事の行をそのまま。`sid` も付いたまま）
{"seq":17,"state":"starting"}                               ← 起動中／停止中（"down"）。この打鍵は処理されなかった
{"event":"state","state":"starting"}                        ← 状態が変わった（要求と無関係に届く）
{"event":"reset"}                                           ← エンジンが終了した。変換中のものは失われた
{"event":"keymap","keymap":{…}}                             ← 食べる表が変わった
```

`state` は `ready` `starting` `down` の 3 つ。キー要求の `t` は、TIP がキーを処理するときに
`QueryPerformanceCounter` から付けたミリ秒（TSF はキーの時刻を渡さない）。`mods` は小文字名の配列
（`["shift","ctrl","alt","win"]` の部分集合）。省略したら修飾キー自体の down/up で追跡する。
`caps_lock` は Caps Lock がオンのときだけ `true` を載せ、省略したらオフとする。

入力開始の `down` には、文書から取得した `left_context`（文字列、取得不能なら `null`）と、
同じ位置に反映した最新確定の `after_commit_seq`（番号、切断なら `null`、不明なら省略）を載せられる。
ブローカーは要求をそのまま転送する。採用条件は [変換仕様](CONVERSION.md) §9 を参照。

### ブローカーとエンジン（標準入出力）

- ブローカー → エンジン: `{"op":"open","sid":3}` `{"op":"close","sid":3}` `{"sid":3,"seq":17,"op":"down",…}`。
- エンジン → ブローカー: 準備ができたら `{"ready":true,"proto":1,"warnings":[…],"keymap":{…}}`（`keymap` は食べる表。[KEYBIND.md](KEYBIND.md) §7.1）。以後は要求 1 件に返事 1 件
  `{"sid":3,"seq":17,…}`。ready のあとで見つかった注意は `{"event":"warning","warning":"lm"}` の形で送る（`lm`・`keymap`）。注意が解けたときは `"active":false` を付ける。
- キー設定の読み直しに成功したエンジンは `{"event":"keymap","keymap":{…}}` を送り、ブローカーが各 TIP に配る。
  `reload_keymap` の返事は [KEYBIND.md](KEYBIND.md) §8.3。
- 1 セッションを標準入出力で直接動かす `python -m yuragi.ime.server` は、試験と評価用。

### 返事の項目

エンジンの返事（`yuragi/ime/server.py:snapshot`）。

| 項目 | 中身 |
|---|---|
| `composition` / `commit` | 変換中の表示 / この要求で確定した文字 |
| `converted` | 変換中か。文節内入力も含む |
| `direct` / `input_mode` / `pass_through` | 直接入力か / 入力モード（`hiragana`・`katakana`・`half_katakana`・`full_alnum`） / この down・up をアプリに渡すか |
| `phase` | キー表の局面（`empty` `composing` `converting` `selecting` `resizing` `editing` `predicting` `direct`） |
| `eat` / `global` | この down を食べたか / TIP が実行するコマンド（`ime_toggle` など）だったときのその名前。英数（`alnum_mode`）の続きが入力ごと終わったときの `ime_off` も（[KEYBIND.md](KEYBIND.md) §6.5） |
| `eat_pending` / `resolved_keys` | LM 待ちで打鍵を保留した / 保留していた打鍵の元の `seq` と最終の `eat`。コマンドだったときは `global` も（[KEYBIND.md](KEYBIND.md) §8.1） |
| `fsm` / `n_tokens` / `timer` | 同時打鍵の判定の状態 / トークン数 / 次に `timeout` を送る時刻（無ければ null） |
| `suggest_at` | 自動予測を問い合わせる時刻。期限があるときだけ返す |
| `segments` | 各文節・リテラルの `start/end`（トークン位置）、`surface/reading`、`literal/fixed`、`display_start/display_end`（表示のコードポイント位置。TIP が UTF-16 の位置に直す）。半開区間 |
| `focus` | 注目文節の `segments` 内の位置。無ければ -1。`editing` ではその文節に入力中の下線を引く |
| `caret` | 入力中に読みを編集しているときと `editing` のキャレットの位置。表示全体の先頭からのコードポイント数（TIP が UTF-16 の位置に直す）。無ければ、`editing` は注目文節の末尾、ほかは表示全体の末尾 |
| `commit_caret` | 確定してアプリに通すキーで編集位置を保つ場合のキャレット。`commit` の先頭からのコードポイント数。無ければ確定した文字の末尾 |
| `candidates` / `cand_index` / `candidate_kinds` | 注目文節の現在のページ（最大 9 件）/ ページ内の選択位置（無ければ -1）/ 各候補の `dictionary`・`kana`・`literal` など |
| `candidate_notes` | 候補と同じ順の種類の注記。空文字は注記なし。全件に注記がなければ省略する |
| `candidate_page` / `has_next_page` | 0 始まりのページ / 次のページの有無 |
| `predicting` / `suggesting` | 予測候補にフォーカスがある / 自動予測をフォーカスなしで表示する |
| `suggestion_only` | `suggest` の返事。候補窓と自動予測の期限だけを扱う |
| `pending` | LM を待っていて、表示はまだ変わっていない |
| `error` | その要求で例外が出て、セッションを作り直した（「要求 1 件ごとの防壁」） |

### 互換の規則

更新後も、開いたままのアプリには古い DLL が残るので:

- 受け取る側は、**知らない項目を無視し、無い項目は既定値にする。** 項目の数や余分を検査しない。
- プロトコル 1 の中での変更は「項目を足す」だけ。意味を変える・消すことはしない。

## 4. ブローカー（`src/broker/`）

打鍵と返事は `sid` と `seq` で振り分ける。`set_direct` と返事の `direct` から旧 TIP の入力モードを覚え、
`reload_keymap`、状態、注意、キー表の通知も扱う。通信と再起動の判断は OS に依存しない `broker_core` にある。

### 起動と終了

- サブシステムは WINDOWS（コンソールを持たない）。ウィンドウは通知用の非表示ウィンドウ 1 枚だけ。
- 二重起動は名前付きミューテックス `Local\yuragi-ime-broker` で防ぐ。取れなければ黙って終了コード 0。
  試験などで `--pipe` で別のパイプを指定したときは、パイプ名を付けた別のミューテックスにする（動いている製品版と衝突しない）。
- 起動したら `HKCU\Software\yuragi-ime\Tag` を読み、自分のタグと違えば（タグが無くても）黙って終了。
- 終了するのは: パイプで `quit` を受けたとき（インストーラ）、サインアウト。

### エンジンの起動のしかた

`CreateProcessW` で、次のとおり。

- 実行ファイルは `engine.json` に書いてある絶対パスの `python.exe` だけ。無ければ起動しない。
- フラグは `CREATE_NO_WINDOW`。同梱ランタイムの `python.exe` はランチャーを挟まないので、子も孫もコンソールを作らない。
- 環境変数は引き継がない。`CreateEnvironmentBlock` で利用者の既定の環境を作り、
  `PYTHONUTF8=1` `PYTHONIOENCODING=utf-8` `PYTHONNOUSERSITE=1` `HF_HUB_OFFLINE=1` を足し、
  `PYTHONPATH` `PYTHONHOME` を消す。
- 標準入力・標準出力は無名パイプ（ブローカーとの通信）。標準エラーは `logs\engine.log`
  （起動のたびに前の分を `engine.prev.log` に回す）。
- ブローカー・エンジン・停止通知のログは各 1 MiB で 2 世代。次の行で上限を超える前に現在のログを `*.prev.log` に回す。
- 「ブローカーが死んだら子も死ぬ」ジョブ（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）に入れる。孤児を残さない。
- 作業フォルダは `versions\<tag>\app`。

### 見張り

```
            ready 受信
 STARTING ───────────────► READY
    ▲  │                     │
    │  │ 終了（無応答で強制終了を含む）
    └──┴─────────────────────┘  ENGINE_EXIT_WINDOW_MS の間の ENGINE_MAX_EXITS 回目の終了なら ──► FAILED
                                                                  │
 STARTING ◄──────(利用者が「もう一度試す」／次のサインイン)────────┘
```

- **終了の検知**は、標準出力と標準エラーが閉じてから、プロセスのハンドルを待つ（ポーリングしない。出力を読み終えてから終了を扱う）。
- **無応答の検知**: エンジンに渡した要求の返事が `ENGINE_HANG_MS` 来なければ、エンジンを強制終了して
  「終了」と同じ扱いにする。エンジンは必ず即答する（LM 待ちは `pending` で即答）。
- **起動の期限**: 起動してから `ENGINE_START_MS` たっても ready が来なければ、同じく強制終了して「終了」と同じ扱いにする
  （通知の理由は無応答）。`--selftest` の起動の期限も同じ値。
- 終了したら、すぐ起動し直す。FAILED に入ったら「通知」を 1 回出し、以後、自分からは何も起動しない。
  終了コードは `broker.log` に残す。
- 利用者の「もう一度試す」（設定を変えたあとの再起動も同じ）は、数えた回数を 0 に戻して起動する。
- ready のあとにエンジンが終了コード `ENGINE_RESTART_CODE`（75）で終わったら、それは**計画した再起動**
  （LM の装置を選び直す。CONVERSION「装置とモデル」）で、回数に数えずにすぐ起動し直す。エンジンは、
  打鍵から `IDLE_BEFORE_RESTART_S`（60 秒）たち、どの接続にも変換中の入力が無いときにだけこれを行う。

### 使えない間の打鍵

- 状態が `ready` でなければ、`reload_keymap` には `{"seq":n,"keymap_reload":"deferred"}` を返す。
  キー表は次のエンジンの起動時に設定ファイルから読む。
- 打鍵は預からない。状態が `ready` でない間に届いた打鍵には、すぐ `{"seq":n,"state":"starting"}`（FAILED 中は
  `"down"`）を返す。TIP はその打鍵からアプリへ素通しにする。
- エンジンが終了したら、処理中だった要求に `{"seq":n,"state":…}` を返し、全接続へ `{"event":"reset"}` を送る。
  新しいエンジンが `ready` になったら、接続ごとに新しいセッションを開く（かな入力で始まる）。
  TIP は `ready` を受け取ったとき、ひらがな以外の入力モードなら `set_mode` を、直接入力なら `set_direct` を送り直す。準備中に切り替えキーを押したときも、
  TIP は手元の入力モードだけを切り替えて、`ready` になってから送る。
- 注意（`lm`・`keymap`）はエンジンごと。エンジンを起動し直したら消し、新しいエンジンが言うものだけを持つ。

## 5. エンジン（`yuragi/`）

- 入口は `yuragi/engine.py`。起動直後に本物の標準入力と標準出力を通信専用に確保し、`sys.stdout` は標準エラーに
  向け直す（ライブラリが `print` しても通信に混ざらない）。プロセスの標準入力は NUL にする。標準入力が閉じたら終了する。

> **注意**: 通信をプロセスの標準入力のまま読まない。Windows では、標準入力のパイプを同期で読み待ちしている間、
> 別のスレッドで標準入力を調べる DLL（torch の読み込みで入る numpy の OpenBLAS）を読み込むと、次のメッセージが
> 届くまで止まる。サインイン後に誰も打たないと、LM がいつまでも読み込まれない。
- セッションは `sid` ごとに 1 つ。辞書・表・学習履歴・個人辞書は全セッションで共有する。
  要求は 1 本のスレッドで順番に処理する。LM は別スレッド（CONVERSION「言語モデル」）。
- **ネットワークに一切つながない。** LM は `local_files_only=True` で読む。

### 起動時の読み込み

利用者が触れるファイルは、壊れていても起動を止めない。プログラム自身のファイルが壊れていたら、はっきり止まる。

| ファイル | 壊れていたら | 利用者への知らせ |
|---|---|---|
| `config.json`（構文・値） | すべて既定値 | なし（ログに 1 行） |
| `personal_lexicon.jsonl` の壊れた行 | その行だけ飛ばす | 設定ウィンドウに件数 |
| `learning.jsonl` の壊れた行 | その行だけ飛ばす | 設定ウィンドウに件数 |
| 辞書キャッシュが読めない | 辞書を読み直し、キャッシュの作り直しを試みる。その間は準備中 | 準備中の表示 |
| 辞書ファイルが無い | **止まる** | 停止の通知 |
| LM のモデル・torch が読めない、またはどの装置・モデルも遅すぎる（CONVERSION「装置とモデル」） | LM なしで動く | 設定ウィンドウの注意（`lm`） |
| `keymap.json` や選んだプリセットが使えない（KEYBIND §5.4） | 起動時は同梱の `ms-ime.json` を使い、稼働中の読み直しでは前の表を使い続ける | 設定ウィンドウの注意（`keymap`） |
| Python のモジュールが読めない | **止まる** | 停止の通知 |

辞書キャッシュは、一時ファイルに書いてから置き換える。
開発の作業ツリーで辞書のテキストを手で直したときは、キャッシュを消す。

> **注意**: 辞書の読み込みで、欠けたファイルや読めない行を黙って飛ばさない。辞書の一部（`suffix.txt`）が
> 欠けたまま作ったキャッシュは、変換の質を少し落とすだけなので、気づかれずに使われ続ける。

### 暖機

`ready` を出す前に、ダミーの変換を 1 回実行する。利用者の最初の打鍵が遅くならない。

LM はそのあとワーカーで読み込み、使い始める前に同じダミーの入力を 1 回 LM で変換する（読みの選択と zenz の確認）。
読み込みが済んだあとの最初の変換から、LM も定常状態の速さになる。かかった時間は `engine.log` に
`warm-up conversion … ms` と残す。

### 要求 1 件ごとの防壁

要求処理ループは、要求 1 件の処理全体を 1 つの `try` で囲む。例外が出たら:

1. `logs\engine.log` に、例外の型と発生箇所（ファイル名・行番号・関数名）を書く。入力した文字は書かない。
2. そのセッションを作り直す。
3. `{"sid":…,"seq":…,"error":true, …作り直したあとの状態… }` を返す。

エンジンは落ちず、TIP は見えている文字をそのまま確定する。防壁はここ 1 か所だけに置き、変換の中身
（`session.py` 以下）には置かない。

### 入力の長さ

変換中の入力は `MAX_TOKENS` まで。達したら、文字キーは受け取るが黙って何も変えない。
変換時間は長さに比例するので、1 回の要求の所要時間に上限が付く。

### 学習履歴のファイル

記録の形式と変換への効き方は CONVERSION「学習」。ここではファイルの扱いだけを決める（`learning.py`）。

1. **自分が書いた分は読み直さない。** 追記したら、同じ行をメモリ上の索引にも足し、
   書いたあとのファイルの大きさと更新時刻を覚える。
2. **他のプログラム（設定ウィンドウ）が書いたら、全体を読み直す。** 変換のたびにファイルの大きさと
   更新時刻を見て、覚えているものと違えば、最初から読み直す。
3. **整理は起動時に 1 回。** 行数が「生きている記録の 2 倍」かつ `COMPACT_MIN_LINES` を超えていたら、
   生きている記録だけを一時ファイルに追記順で書いて置き換える。語と区間それぞれで、抑制されていない（読み・表記）と
   （読み・左側の表記・表記）ごとの最新行を残す。変換に使わない行（CONVERSION「学習」の `choice` の無い行）も、
   （読み・表記）ごとの最新行を残す（利用者のデータなので消さない）。追記と整理は同じ履歴のロックを使い、
   履歴の再読込から書き込み後のファイル状態の取得までを同期する。`learning.jsonl.lock` はこの同期に使う。
   整理では `learning.jsonl.tmp` に書いてから置き換える。書き込みや置き換えに失敗したときは一時ファイルが残ることがある。
4. 行ごとの検査は、「JSON として読めて、必要な項目がある」だけ。

学習の入／切は `config.json` の `learning` で決める。ファイルは最初に記録するときに作る。

## 6. TIP（`src/tip/`）

TSF とのやりとり（キーの受け取り、変換中の文字の描画、表示属性、候補ウィンドウ、言語バー、トグルキー）と、
ブローカーとの接続（`BrokerLink`）。判断のうち TSF に依存しないもの（返事の解釈、食べるかどうか、
返事の順序、状態と表示）は `src/tip/tip_logic.h` にある。エンジンの起動・見張り・再試行、Python の探索と起動、
設定ウィンドウの起動は持たない。ログは `tip.json` の `log:true` のときだけ書く。

> **注意**: TIP の中で入力を待たない。`ActivateEx` で辞書の準備などを待つと、Windows 11 の
> TextInputHost が止まり、すべての IME が使えなくなる。

### 接続

- `Tip` 1 個につき、パイプ 1 本と読み取りスレッド 1 本。
- 読み取りスレッドは、届いた 1 行ごとに手元の列に積み、TIP のメッセージ専用ウィンドウへ `PostMessage` するだけ。解析は UI スレッドで行う。
  待つのは「パイプの読み取り」「停止の合図」「接続の合図」の 3 つ。時間で回るのは、パイプが現れるのを待つ間
  （ブローカーを起動したあと、またはパイプがすべて塞がっているとき。`BROKER_POLL_MS` 間隔で最大 `BROKER_WAIT_MS`）だけ。
- 接続を試すきっかけは 4 つだけ: `ActivateEx`、かな入力モードで打鍵があったとき（`OnTestKeyDown` で素通しと答えたキーも。
  IMM 経由のアプリはそのキーで `OnKeyDown` を呼ばない）、利用者がメニューで「もう一度試す」を選んだとき、
  設定ウィンドウを開くとき（メニューの「設定を開く」、単語登録などのキー）。前の 2 つは、前回の試みから
  `CONNECT_MIN_INTERVAL_MS` 以内なら試さない。利用者の操作による後の 2 つは、間隔を問わない。
  つながっている間と、試している間は、どのきっかけでも新しく試さない。
- 設定ウィンドウを開く依頼は、つながっていなければ覚えておき、その操作で始めた接続がつながったときに送る（つながらなければ捨てる）。
- hello は読み取りスレッドが接続の直後に書く。そのあとの書き込みは UI スレッドから。重ね合わせ I/O で、その呼び出しの `KEY_BUDGET_MS` の残りのうちに書けなければその打鍵は素通し。

### ブローカーを起動する条件

パイプが無かったとき、**次の全部が成り立つ場合に限り**、ブローカーを起動する。条件に合わないプロセスは接続するだけ。

1. `HKCU\Software\yuragi-ime\Tag` が、この DLL のタグ（ビルド時に埋め込む）と同じ。
   ——アンインストール済み・更新済みの古い DLL は、ここで必ず止まる。
2. このプロセスが、サンドボックスの中でなく、管理者権限でもない（整合性レベルが「中」）。

回数は数えない。ブローカーの二重起動防止と、接続を試す間隔で足りる。

実行ファイルは**この DLL と同じフォルダ**の `yuragi-broker.exe`。フラグは
`CREATE_NO_WINDOW | CREATE_BREAKAWAY_FROM_JOB`、ハンドルは引き継がない、環境は `CreateEnvironmentBlock` で
作ったもの（作れなければアプリの環境のまま）。起動に失敗したら（ジョブからの離脱が許されない環境を含む）、その場ではやり直さない。
起動したら、パイプが現れるのを最大 `BROKER_WAIT_MS` 待つ（`BROKER_POLL_MS` 間隔）。

通常はサインイン時に Run キーでブローカーが起動しているので、この経路は「ブローカーが何かで消えた」ときの回復用。

### 打鍵の処理

次のときは食べず、何も送らない: キーボードが無効、フォーカスのある文書が無い、
パスワード欄（切り替えキーも食べない）、直接入力、ブローカーにつながっていない、エンジンが `ready` でない
（準備中の切り替えキーだけは食べて、手元の入力モードを切り替える。「使えない間の打鍵」）。
Windows 側で IME が閉じている間は通常の打鍵を通す。有効な入力欄で Alt+`` ` `` などのオン操作を受けると、
Windows 側の IME を開き、指定された入力モードにする（[KEYBIND.md](KEYBIND.md) §7.5）。
それ以外のキーで食べるかは、エンジンから受け取った食べる表で決める（[KEYBIND.md](KEYBIND.md) §7）:

1. `OnTestKeyDown`: 食べる表と手元の局面だけで「食べるか」を答える（通信しない）。
   **返事を待っている要求があれば、入力がある局面のどれかで受け取るキーは受け取る**——後から来た Enter や BS が先にアプリへ抜けない。
2. `OnKeyDown`: 1 と同じ答えを返す。打鍵の時刻 `t` を記録し、かな入力の開始時だけ（返事待ちで、開始かどうかが手元で分からないときも）、同期の読み取りセッションで文書の左文脈を取得する（`tip.json` の `document_context` が有効なとき）。
   通し番号 `seq` を付けて要求を送り、`t` から `KEY_BUDGET_MS` の期限までその番号の返事を待つ。
   - **間に合った** → 同期の編集セッションで画面に反映する。返事が `eat:false` なら、反映のあとでキーを送り直す（KEYBIND §7.6）。
   - **間に合わなかった** → 1 の判定どおりに食べて、すぐ戻る。接続は切らない。画面も触らない。
     返事は後で読み取りスレッドから届き、非同期の編集セッションで反映する。
3. 返事は必ず `seq` の順に反映する。前の返事がまだなら、届いても待たせる。
4. 返事が `{"seq":n,"state":"starting"}`（または `"down"`）なら、その打鍵は送り直してアプリへ渡し、以後は状態が
   `ready` に戻るまで送らない。

> **注意**: 返事を見て `OnKeyDown` で通す、としない。先に `OnTestKeyDown` を呼ぶアプリ（Word などの IMM 経由のアプリ）では、
> `OnTestKeyDown` で食べると答えたキーは `OnKeyDown` で通してもアプリに届かず、失われる（[keybind/windows.md](keybind/windows.md) §1.1）。
> 通すのが効くのは `OnKeyDown` だけを呼ぶアプリ（メモ帳、Chromium、ターミナル）だけ。アプリに渡すべきだったキーは送り直す（[KEYBIND.md](KEYBIND.md) §7.3・§7.6）。

食べたキーをあとからアプリに渡す間と、返事を待つ間に押されたキーは、TIP が食べて手元に溜める。
溜めたキーを黙って消さないこと、あとのキーに追い越させないことの規則は [KEYBIND.md](KEYBIND.md) §7.6・§7.7。

### 見えている文字の確定

次のどれかを受け取ったら、変換中の文字列があれば**その表示のまま確定して**（文字は消さない）、手元の状態を初期化する。

- `{"event":"reset"}`（エンジンが終了した）
- 返事の `"error":true`
- 返事・通知の `state` が `down`
- パイプが切れた（ブローカーが消えた）
- 入力モードの切り替えをエンジンに送れなかったとき

文字を消してよいのは、利用者が Esc を押したときと、フォーカスが移ってアプリが変換を打ち切ったときだけ。

フォーカスの移動、アプリによる変換終了、入力モードの切り替え、切断では、古い応答と未適用の編集要求を破棄する。
同じ入力欄に戻っても、古い応答は反映しない。

食べたまま手元に溜めてあるキー（返事や送り直しを待つ間に押されたキー）は、この破棄に含めない。
行き先は [KEYBIND.md](KEYBIND.md) §7.6・§7.7 で決める（処理を続ける、移動先へ持ち越す、記録して捨てる、のどれか）。

### タイマー

- 返事に `timer`（同時打鍵の判定期限、LM 待ちの次の問い合わせ時刻）があるときは、
  その時刻に 1 回鳴るタイマーを掛ける。鳴ったら `timeout` を送る。
- `suggest_at` も同じタイマーで扱い、打鍵の返事を待っておらず、送る打鍵も無いときだけ `suggest` を送る。
  自動予測の期限と返事待ちはキーの判定に使わない。後続の要求を送っていれば `suggest` の返事を表示せず、
  フォーカスが変われば通常の変換と同様に捨てる。
- タイマーを掛け直すたびに新しい ID を使い、取り消したタイマーの通知が届いても無視する。
- 候補ウィンドウの位置は、TSF の配置変更通知（`ITfTextLayoutSink::OnLayoutChange`）で直す。

### 32 ビットのアプリ

アプリは自分と同じビット数の DLL しか読み込めない。64 ビット版だけだと、32 ビットのアプリ
（サクラエディタの公式版など）ではゆらぎを選んでも TIP が読み込まれず、キーがそのまま英字で入る。
そこで同じソースを x86 でもビルドし（`yuragi_tip32.dll`）、64 ビット版と同じフォルダに置く
（どちらも隣の `yuragi-broker.exe` を起動できる。ブローカーは 64 ビットの 1 つだけ）。

- CLSID は同じ。COM の登録（`InprocServer32`）はレジストリの 32/64 ビットの側にそれぞれある。
  TSF の登録（`HKLM\SOFTWARE\Microsoft\CTF\TIP`）は両方に共通で 1 つ。MS-IME と同じ形。
- 登録は 32 ビット版を先に、64 ビット版を後に `regsvr32` する（共通の TSF 登録のアイコンが 64 ビット版を指す）。
- 解除は、TSF の登録が既に無ければ COM の登録だけを消す（2 つ目の解除が失敗にならないように）。

### パスワード欄

入力欄の種類（`IS_PASSWORD`・`IS_NUMERIC_PASSWORD` ならパスワード欄）は、フォーカスが移ったときに 1 回
調べて覚える（読み取り専用の編集セッション）。同期で調べられなければ非同期で頼み、答えが出るまでは
素通しにする。「選択範囲が取れない」「入力欄の種類が取れない」は、パスワード欄の証拠として扱わない。
左文脈の本文を読むときは入力欄の種類を再確認する。入力スコープの照会に失敗した場合は本文の取得を見送る。

**素通しの例外。** 前の欄で食べて手元に溜めたキーを持ち越している間（[KEYBIND.md](KEYBIND.md) §7.7）だけは、答えが出る前に押されたキーも食べて、
溜めたキーの後ろに並べる。通すと、溜めてあるキーより先に届いて順序が入れ替わるため。このとき次を守る。

- 並べたキーは TIP の中に置くだけで、答えが出るまでエンジンにも記録にも出さない。
- 答えがパスワード欄なら、溜めたキーも並べたキーも、エンジンに送らずに同じキーのまま順に Windows に返す（`SendInput`）。
  答えが `KEY_BUDGET_MS` のうちに出なければ、パスワード欄と同じに扱う。
- 溜めたキーが無くなれば、ふつうの規則（パスワード欄と未判定の欄は素通し）に戻る。

溜めたキーの無いふつうの移動では、この例外は働かない。

## 7. インストール・更新・アンインストール

### 共通の仕組み

- **取得物の版と照合**
  - リリースの配布物は指定したタグのものを取得する。
  - Python の埋め込み版は `python.org` から指定した版を取得し、`setup.ps1` に記載した SHA-256 と照合する。
  - Mozc 辞書は上流のコミットを指定し、取得したファイルを辞書マニフェストの SHA-256 と照合する。
    上流のコミットとファイルの一覧・ハッシュは、マニフェスト（`data/dictionary-manifest.json`）の 1 か所にだけ書く。
  - `get-pip.py` は `bootstrap.pypa.io` から取得し、pip を PyPI から入れる。どちらも版とハッシュの指定は無い。
  - torch は PyTorch から、種類（`cpu`・`cu126`・`cu128`）ごとの wheel の SHA-256 を `setup.ps1` に固定して
    `--no-deps` で入れる。transformers と、torch と transformers が要るものはすべて、版と SHA-256 を
    `packaging/requirements.txt` に固定し、PyPI から `--require-hashes` で入れる（書いていないもの、ハッシュの違うものは入らない）。
  - pip は利用者の pip の設定（`pip.ini`・`PIP_*` の環境変数）もキャッシュも使わない（`--isolated --no-cache-dir`）。
  - 言語モデルは Hugging Face のリビジョンを指定し、エンジンが読むファイルを、`packaging/fetch_model.py` に
    固定した大きさと SHA-256 と照合する。
  - 版と出典の一覧は [NOTICE.md](../NOTICE.md) を参照。
- **README の 1 行の形**: 「前回の残り（`%TEMP%\yuragi-setup.ps1`）を消す → 取得 → 取得できたとき（`$?`）だけ実行」。
  取得に失敗したとき、前回取得した古いスクリプトは走らない。Windows PowerShell 5.1 には `&&` が無いので
  `if ($?)` で書く。アンインストールの 1 行と、setup が最後に表示する 1 行も同じ形。
- **管理者権限で行うのは 3 つだけ**（UAC は 1 回）: ①`Program Files` へのファイルの配置、
  ②`regsvr32` による登録／解除、③古い版の `Program Files` 側の削除。
  これは `packaging/elevated.ps1` にまとめ、**Python は管理者権限で動かさない。**
  呼び出しは `-EncodedCommand`（空白・引用符・日本語を含むパスも崩れない）。結果は終了コードと、
  利用者側が読める結果ファイルで返す。
- アンインストールは `Program Files` の `elevated.ps1` を使う（管理者だけが書ける）。
- **1 台を複数の利用者で使うことは対象外**: `Program Files\yuragi-ime\` と HKLM の登録は 1 台に 1 つで、
  更新は入れる版以外を `Program Files` から消し、アンインストールは登録ごと消す。他の利用者のゆらぎは、そのとき動かなくなる。
- **使用中のファイル**: 消せないファイル（アプリが読み込んでいる DLL）はそのまま残し、次の実行で消す。
  版ごとのフォルダなので、残っても邪魔にならない。`DllUnregisterServer` は、どれか 1 つでも失敗したら失敗を返す。
- **言語一覧への追加・削除**（`InstallLayoutOrTip`）は利用者ごとの設定なので、管理者権限でない側で行う。

### インストールと更新（同じ手順、`setup.ps1`）

README の 1 行で `setup.ps1` を取得して実行する。管理者ではない普段の PowerShell から実行する
（管理者権限が要る段 5 で確認が 1 回出る）。

| 段 | すること | ここで失敗したら |
|---|---|---|
| 1 | リリース版の setup.ps1 であることと、動作環境（64 ビット・Windows 10 以降・ディスクの空き）を確かめる | — |
| 2 | `staging\<tag>\` に取得・照合・展開。足りない共有物（ランタイム・辞書・モデル）だけ `shared\` に作る。共有物は「作りかけの名前で作って、完成したら改名」（途中で止まったものは次に作り直す）。ランタイムは Python の埋め込み版に、リリースに添えた同じ版の tkinter 一式（`python-<版>-tkinter-amd64.zip`）を重ね、torch・依存・tkinter とあわせて読み込めることを確かめる。torch は、`nvidia-smi` で CUDA 対応の GPU とドライバが見つかれば GPU 版（`cu128`／`cu126`。ディスクの空きが 10GB 以上のとき）、無ければ CPU 版。GPU 版のランタイムは名前に `-cu128` などが付く別の共有物。言語モデルは CPU 用の zenz-v2.5-small を常に、GPU 版 torch なら GPU 用の zenz-v2.5-medium も取る（どれを使うかはエンジンが起動のたびに実測で決める）。`-Cpu` を付けると GPU があっても CPU 版 | 何も変わっていない。旧版が動き続ける。やり直せば続きから |
| 3 | **本物のブローカーで試運転**: `yuragi-broker.exe --selftest <staging の engine.json>`。エンジンを実際に起動し、変換を 1 回行って終了コードを返す。エンジンは `--require-lm` 付きで、LM を読み込んで暖機できなければ失敗する（LM なしのまま「完了」にしない）。利用者のデータは使わない | 同上 |
| 4 | `staging\<tag>` を `versions\<tag>` へ改名（一瞬）。`versions\<tag>` が既にあれば脇へ寄せる。それが入っている版（Tag が同じ）なら同じ版の入れ直しで、先にそのブローカーを止める。違えば前回の途中の残りで、動いている版には触らない | 切り替えを完了できなかったことを表示し、再実行を案内する |
| 5 | 旧ブローカーに `quit`。管理者権限: そのブローカーの終了を待ち（最大 15 秒。旧版の exe も消せるように）、`Program Files\yuragi-ime\<tag>\` に配置、登録を新しい DLL（64・32 ビット）に付け替え、旧版を消す | エラーの理由を表示し、再実行を案内して停止する |
| 6 | 旧ブローカーが残っていれば止める。`HKCU\…\Tag` と Run キーを新しい版に書き換え、言語一覧に追加 | 言語一覧に追加できなければ、切り替え済みと表示して停止する。新ブローカーは次の打鍵（TIP）かサインイン（Run キー）で起動する。やり直せば最後まで進む |
| 7 | 新ブローカーを起動して `ready` を待って確認（最大 120 秒） | 理由を表示。次のサインインでも起動を試みる |
| 8 | 旧版の片付け: `versions\` と `shared\` の使われていないもの。`Program Files` 側の旧版は 5 の管理者権限の中で消す（使用中のものは残す） | 片付けの失敗はインストールの失敗にしない。次回の setup がまた試す |

- 試運転までは、動いている版に触らない。5〜7 は数秒。
- インストールを続けられない場合は、理由と切り替えが済んだかどうかを表示し、再実行を案内する。予期しない例外も同じ形で扱う。
- 更新のあと、開いたままのアプリには旧 DLL が残る。旧 DLL は「ブローカーを起動する条件」の 1 で何も起動せず、
  新ブローカーに接続する（「互換の規則」によりそのまま動く）。
- `staging\` は自分の作業場なので、いつでも消して作り直してよい。
- 取得先に届かないネットワークでは、届かなかった取得の段で止まる。
- 署名なしの DLL とブローカーは、Smart App Control やウイルス対策に止められ得る。止められた場合は、
  試運転（段 3）か起動の確認（段 7）が理由を表示して止まる。
- ARM 版の Windows では、setup が最初に「ARM 版 Windows には対応していません。」と表示して止まる。

### アンインストール

リリースの `uninstall.ps1` は入口（`packaging/uninstall-entry.ps1`）で、HKCU の Tag で入っている版を見つけ、
その版の本体（`versions\<tag>\app\packaging\uninstall.ps1`）を、引数（`-RemoveData` `-Yes`）をそのまま渡して呼ぶ。
Tag が無いか、その版の本体が無ければ「インストールされていません」と表示して終わる（`-RemoveData` なら、残っている `~\.yuragi-ime\` を確かめてから消す）。Tag が `dev`（開発用の登録）なら、リポジトリの `packaging\uninstall.ps1` を使うよう伝えて止まる。本体がすること:

1. Run キーを消し、言語一覧から外す。
2. ブローカーに `quit`（エンジンも終了する）。
3. 管理者権限: 登録解除。`Program Files\yuragi-ime\` を削除。使用中のファイルは残す。
4. HKCU の `Software\yuragi-ime`（Tag）と、言語一覧から外したときに Windows が書く
   TSF の利用者設定（`SOFTWARE\Microsoft\CTF\TIP\{CLSID}`）を削除。`%LOCALAPPDATA%\yuragi-ime\` を削除。
   Tag は登録解除のあとで消すので、途中で止まっても、入口からやり直せる。
5. 結果を表示する。サインアウトや再起動を求めない。

`~\.yuragi-ime\`（学習履歴・個人辞書・設定）は残す。消すのは `-RemoveData` を付けたときだけで、
そのときも消す前に場所と大きさを表示する（`-Yes` で確認を省く）。

### 開発時（`dev-build.ps1`・`dev-register.ps1`）

- `src\tip\dev-build.ps1`: TIP（64・32 ビット）とブローカーを Release でビルドして試験し、`dist\yuragi_tip.dll`・
  `dist\yuragi_tip32.dll` と `dist\yuragi-broker.exe` を作る（管理者権限・登録なし）。リリースのワークフローもこれを使う（CI は cmake を直接呼ぶ）。
- `src\tip\dev-register.ps1 [-Python <python.exe>]`: タグ `dev` として登録する（UAC 1 回）。
  `HKCU\…\Tag = dev`、`versions\dev\engine.json` はリポジトリを指す。エンジンは `-Python` の Python で動く（torch と transformers が要る）。
  `-Python` を省くと、入っている製品版の `engine.json` から同梱の Python、辞書、キャッシュ、LM のモデルを借りる。
  開発登録は `--require-lm` を付けて起動する。設定が `lm_rescore: false` でも zenz を暖機し、成功してから
  `ready` を返す。モデルの読み込みや暖機に失敗すると終了する。
  DLL とブローカーは `dist\` から読み込む（開発機に限り `Program Files` 配置を省く）。DLL は
  `dist\yuragi_tip-a.dll`、`-b.dll`、… のうち、登録中でも使用中でもない最初のものにコピーして登録するので、
  古い DLL を読み込んだアプリを閉じなくても入れ直せる。
- 開発登録は 64 ビット版だけ（32 ビットのアプリでは動かない）。32 ビットを試すときは `setup.ps1 -AssetDir` で入れる。
- 外すときは、製品版と同じ `packaging\uninstall.ps1`（`dev-register.ps1` が `dist\` に置く `elevated.ps1` を使う）。

## 8. 利用者に見えるもの

普通の利用者は「ゆ」と「Y」以外のものを見ない。見せるのは、利用者が何かしないと直らないときだけで、
何が起きたか・文字は無事か・どうすればよいか、を 1 つの文で言う。どれもフォーカスを取らない。
利用者向けの説明は [USAGE.md](USAGE.md)。

### 状態

| 状態 | タスクバー | 打鍵 | いつ |
|---|---|---|---|
| 通常 | 「ゆ」／「Y」 | 変換される | ほぼ常に |
| 準備中 | 「ゆ」／「Y」（薄く） | そのまま通る（直接入力と同じ）。切り替えキーは効く | サインイン直後の数秒、エンジンの起動し直し中 |
| 停止 | 「!」 | そのまま通る | 自動で直せなかったとき |
| 対象外 | 「Y」 | そのまま通る | この利用者には未インストール、サンドボックス・管理者のアプリでブローカーが無い、パイプの相手がブローカーでない |

### 候補窓の描画

Windows 11 の MS-IME に合わせ、角丸の面に番号と候補を並べる。選択行には淡い角丸の地と Windows のアクセント色の短い縦線を使う。窓の角丸と影は DWM に任せ、細い枠と中身は不透明な面に GDI で描く。候補窓と小さな表示はどちらもフォーカスとクリックを素通しする。

- Windows のアプリの色モードに合わせてライト／ダークを切り替える。ハイコントラストでは、文字・地・枠・選択色を Windows のシステム色から取る。設定変更の通知で配色を更新する。
- 寸法と配置は `tip_logic.h` で計算する。行は 32 DIP を基準に、表示先の DPI で拡大する。候補の文字幅と注記を測り、幅の上限または作業領域を超える文字は末尾を省略する。作業領域の下端ではキャレットの上へ回す。番号は独立した列に小さく右寄せする。
- TIP は DPI に合わせたフォントを使い回し、裏画面から一度に転送する。候補、ページ、通知の切り替えは即時に描画する。
- 注記はエンジンが生成した表記の種類を示す。かな候補には「ひらがな」または「カタカナ」、記号辞書の候補には「記号」、数字・リテラル・英数の半角候補には「半角」を添える。辞書の候補は候補の文字だけを表示する。
- 2 ページ目以降、または続きがあるときは、窓の下端に現在のページを 1 から数えて表示する。続きがあれば下向きの印を添える。総ページ数は遅延生成のため未確定とする。
- 自動で出る予測候補は、番号と選択行を出さず、下端に「Tab で選択」と表示する。TIP は読み取り用の編集セッションで窓を配置する。


### 小さな表示

候補ウィンドウと同じ作り（`WS_EX_NOACTIVATE`。フォーカスもクリックも取らない）で、文字入力位置の下に 1 行だけ出す。
出すのは 1 種類だけ。

| いつ | 文言 | 消える条件 |
|---|---|---|
| 停止中に、かな入力のつもりで文字キーを押した（フォーカスごとに 1 回） | `日本語変換が止まっています。タスクバーの「!」を右クリックしてください` | `NOTICE_SHOW_MS` |

### 通知

ブローカーが、停止に入ったときに 1 回だけ、Windows の通知（`Shell_NotifyIcon`。フォーカスを取らない）で出す:

> **ゆらぎ: 日本語変換が止まりました**
> 入力済みの文字はそのまま残っています。ここを押すと、もう一度試せます。

押すと、ブローカーがネイティブのダイアログ（`TaskDialogIndirect`。Python が壊れていても出せる）を開く。
本文は「変換エンジンが繰り返し止まったか、反応しなくなりました。「もう一度試す」で起動し直します。
直らなければ、インストールの1行をもう一度実行してください。」、ボタンは `もう一度試す`
`記録のフォルダを開く` `閉じる`。ダイアログは 1 枚だけで、開いている間にもう一度押すと前に出す。ほかの経路の「もう一度試す」などで停止が終わったら閉じる。原因（終了コード）は `broker.log` に残す。

起動はできている軽い異常（LM が使えない）は、`broker.log` と設定ウィンドウの「状態」タブの「注意」に出す。
止まったことは `logs\notices.log` にも残す（設定ウィンドウの「最後に止まった理由」）。

### メニュー

タスクバーの「ゆ」「Y」を右クリックする。通常動作中は、かな入力で未確定の文字がないときに Ctrl+F10 でも開ける。
Ctrl+F10 ではキャレットの近くに開く。Windows からキャレット位置が取れないときは、フォーカスのある窓の左上に開く。

| 状態 | 項目 |
|---|---|
| 通常 | `直接入力に切り替え`／`かな入力に切り替え`、`設定を開く` |
| 準備中 | `（変換の準備をしています）`（押せない）、`設定を開く` |
| 停止 | `もう一度試す`、`設定を開く` |
| 対象外 | `設定を開く` |

設定ウィンドウは TIP が起動するのではなく、ブローカーに `open_admin` を頼む（ブローカーが `pythonw.exe` で起動）。
設定ウィンドウの「状態」タブに、ブローカーとエンジンの状態・注意・最後に止まった理由・学習履歴の行数を出す。
「状態」タブの「変換エンジンを再起動」は、ブローカーへの `retry` で行う。
「キー」タブで保存した割り当ては、エンジンを再起動せずに反映する。[KEYBIND.md §8.3](KEYBIND.md#83-設定を変えたときの流れ)

## 9. 実地試験

Windows サンドボックスか仮想マシンで、各操作の間、新しく生まれたプロセスと新しく現れた最上位ウィンドウを記録する。
メモ帳・ブラウザ・エクスプローラ・32 ビットのアプリ（サクラエディタ）を開き、IME を選んで打鍵した状態から始める。

| # | 操作 | 期待 |
|---|---|---|
| 1 | インストール → IME を選ぶ → かなを打って変換（32 ビットのアプリでも） | 変換できる。常駐はブローカー 1・エンジン 1。ウィンドウ 0 |
| 2 | 変換の途中でエンジンをタスクマネージャーで終了し、打ち続ける | 見えていた文字が残る。起動し直す間の打鍵はそのまま（英字で）入り、数秒後から変換される。ウィンドウ 0 |
| 3 | エンジンを 10 分以内に 3 回終了 | 3 回目で「!」と通知 1 回。以後、起動 0 回 |
| 4 | メニューの「もう一度試す」 | 戻る |
| 5 | ブローカーをタスクマネージャーで終了し、打鍵する | 数秒で戻る |
| 6 | `config.json` を壊してサインインし直す | 変換できる（既定の設定で） |
| 7 | 辞書ファイルを 1 つ消してサインインし直す | 「!」と通知 1 回。起動はちょうど 3 回 |
| 8 | **アプリを開いたまま**更新 | 終わる。開いていたアプリでそのまま打てる。学習が残る |
| 9 | 更新の途中（取得中）で回線を切る／setup を強制終了 | 旧版で打てる。やり直すと終わる |
| 10 | **アプリを開いたまま**アンインストール | 終わる。60 秒、プロセス 0・ウィンドウ 0。学習履歴は残っている |
| 11 | スタートメニューの検索欄、「設定」、管理者として開いたメモ帳で打鍵 | 変換できる、または黙って素通し。どちらでもプロセスの起動 0 |
| 12 | 初回インストールの途中で回線を切る → やり直す | 手で何も消さずに終わる |
| 13 | 再起動してサインイン直後に打鍵 | 準備中（薄い「ゆ」）の間はそのまま入り、準備ができたら変換される |

## 10. 定数

|---|---|---|---|
| `KEY_BUDGET_MS` | 200 | TIP | 打鍵 1 回（Windows からの呼び出し 1 回）で UI スレッドが待つ上限。その中の書き込みと返事待ちをすべて含む |
| `CONNECT_MIN_INTERVAL_MS` | 2000 | TIP | 接続の試み（とブローカーの起動）の最小間隔 |

| `CONTEXT_CHARS` | 200 | TIP・エンジン | 入力の開始に添える文書の左文脈の長さ（コードポイント） |
| `PIPE_BUFFER` | 64 KiB | ブローカー | TIP とのパイプの送受信のバッファ |
| `NOTICE_SHOW_MS` | 4000 | TIP | 小さな表示の表示時間 |

| `MAX_TOKENS` | 200 | エンジン | 変換中の入力の長さの上限 |
| `COMPACT_MIN_LINES` | 5000 | エンジン | 学習履歴の整理を始める行数 |
