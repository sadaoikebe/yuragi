# ゆらぎの全体設計（TIP・ブローカー・エンジン、置き場所、インストール）

ゆらぎを構成するプロセス、その間の通信、ファイルの置き場所、インストールの手順、利用者に見えるものの仕様。
コードのコメントは、この文書の節を名前で参照する（DESIGN「見張り」など）。数値は「定数」の表にまとめ、
本文は名前で書く。変換の中身（打鍵の判定、変換、候補、学習）は [CONVERSION.md](CONVERSION.md)。

---

## 1. 構成

```
アプリ ──[TIP DLL]──(名前付きパイプ)──[ブローカー]──(標準入出力)──[変換エンジン]
          薄い・状態が少ない          小さい・ネイティブ        大きい・Python
          アプリの中で動く            落ちない前提で作る        落ちることを前提に扱う
```

| 部品 | 実体 | 数 | 誰が起動するか | 役目 |
|---|---|---|---|---|
| TIP | `yuragi_tip.dll`（C++） | アプリのスレッドごと | Windows | 打鍵を送り、返事を画面に書く。プロセス管理・再試行・ファイルの読み書きは持たない |
| ブローカー | `yuragi-broker.exe`（C++、ウィンドウなし） | サインインごとに 1 | サインイン時（Run キー）。無ければ TIP が条件付きで | エンジンを起動し、見張り、落ちたら起動し直す。打鍵と返事を配る |
| エンジン | 同梱 Python で `python -m yuragi.engine` | ブローカーごとに 1 | ブローカーだけ | 辞書・学習・LM を抱えて変換する |
| 設定ウィンドウ | `pythonw -m yuragi.ime.admin_ui` | 利用者が開いたとき | ブローカー（TIP のメニューから依頼） | 単語登録・学習・設定・状態 |

### 守ること

| # | 守ること |
|---|---|
| 1 | **打った文字は消えない。** エンジンに何が起きても、画面に出ていた文字はそのまま確定する（「見えている文字の確定」） |
| 2 | **エンジンが落ちても数秒の間で済む。** 起動し直しを決めるのはブローカーだけ。`ENGINE_EXIT_WINDOW_MS` の間に `ENGINE_MAX_EXITS` 回落ちたら止まり、利用者の操作かサインインまで再開しない |
| 3 | **直らない故障は、1 回だけ普通の言葉で知らせる。** 「もう一度試す」がそこにある |
| 4 | **勝手にウィンドウを出さない。フォーカスを奪わない。** 現れるウィンドウは利用者が開いたものだけ。どのプロセスもコンソールなしで起動する |
| 5 | **PC に掛ける負荷に上限がある。** TIP が打鍵 1 回で UI スレッドを止めるのは `KEY_BUDGET_MS` まで。ブローカーを起動してよいのは TIP だけで、間隔は `CONNECT_MIN_INTERVAL_MS` 以上。入力の長さ、ファイルの大きさにも上限がある |
| 6 | **入れる・上げる・消すは、アプリを開いたままで終わる。** どこで失敗しても「前の版が動く」か「新しい版が動く」。「成功」と表示するのは、結果を読み返して確かめたあとだけ |
| 7 | **利用者のデータ（学習履歴・個人辞書・設定）を、頼まれずに消さない。** |

## 2. 置き場所

```
%ProgramFiles%\yuragi-ime\<tag>\          管理者だけが書ける。全アプリに読み込まれるものはここ
    yuragi_tip.dll  yuragi-broker.exe  elevated.ps1

%LOCALAPPDATA%\yuragi-ime\                 利用者の権限で動くものだけ。管理者権限では決して実行しない
    versions\<tag>\app\                     Python のソース
    versions\<tag>\engine.json              このタグが使う共有物への道順（ブローカーが読む。形は src/broker/support.h）
    shared\runtime\<id>\                    同梱 Python + tkinter + torch + 依存。id = 版とハッシュ
    shared\dict\<上流コミット>\             Mozc 辞書
    shared\cache\<辞書マニフェストのハッシュ>.pkl
    shared\model\<リビジョン>\              LM モデル
    staging\                                更新の作業場。成功したら versions へ移す

%USERPROFILE%\.yuragi-ime\                 利用者のデータ。更新でもアンインストールでも触らない
    config.json  tip.json
    learning.jsonl  personal_lexicon.jsonl
    logs\broker.log  logs\engine.log  logs\notices.log（それぞれ前の世代 *.prev.log）

HKLM  CLSID・TIP 登録 → %ProgramFiles%\yuragi-ime\<tag>\yuragi_tip.dll
HKCU\Software\yuragi-ime   Tag = <tag>     「この利用者には、この版が入っている」の唯一の印
HKCU\…\CurrentVersion\Run   yuragi-ime = "…\<tag>\yuragi-broker.exe"
```

- **版ごとにフォルダを分ける。** 更新は「新しいフォルダを作って、登録を付け替える」だけで、
  読み込まれている DLL には触らない。だからアプリを開いたまま更新できる。
- **大きいもの（ランタイム・辞書・モデル）は中身で名前を付けて共有する。** 中身が同じなら更新で取り直さない。
- **学習履歴と個人辞書はプログラムのフォルダの外**に置く。
- **Python は同梱ランタイム 1 本。** ほかの Python を探さない。

## 3. 通信

### TIP とブローカー（名前付きパイプ）

- 名前: `\\.\pipe\yuragi-ime-<利用者の SID>-<セッション番号>`。バイト単位、1 行 1 JSON（UTF-8、`\n` 区切り）。
- アクセス権: その利用者に読み書き。加えて「すべてのアプリパッケージ」（`S-1-15-2-1`）に読み書き
  ——スタートメニューの検索欄など、サンドボックス内のアプリからも**接続だけは**できるようにする。
  接続できないアプリでは、そこでは素通しになる。他の利用者・ネットワークからは不可（`PIPE_REJECT_REMOTE_CLIENTS`）。
- TCP・ポート番号・トークンは使わない。パイプが在ること自体が「ブローカーがいる」の印になる。

TIP → ブローカー（プロトコル 1）:

```json
{"op":"hello","proto":1,"tag":"v0.2.0","bits":64,"passes":true}
{"seq":17,"op":"down","vk":74,"t":123456,"mods":[]}        ← op は down/up/timeout/reset/set_direct
{"op":"retry"}                                              ← 利用者が「もう一度試す」を選んだ
{"op":"open_admin"}                                         ← 設定ウィンドウを開く
{"op":"quit"}                                               ← インストーラだけが使う
```

ブローカー → TIP:

```json
{"proto":1,"state":"ready","warnings":[]}                   ← hello の返事
{"seq":17, …エンジンの返事の全項目… }                      ← 要求の返事（エンジンの返事に seq を付けたもの）
{"seq":17,"state":"starting"}                               ← 起動中／停止中（"down"）。この打鍵は処理されなかった
{"seq":17,"pass_through":true,"direct":false}               ← 同上。hello に passes の無い TIP へ（「使えない間の打鍵」）
{"event":"state","state":"starting"}                        ← 状態が変わった（要求と無関係に届く）
{"event":"reset"}                                           ← エンジンが終了した。変換中のものは失われた
```

`state` は `ready` `starting` `down` の 3 つ。hello の `passes:true` は「`ready` でない間の打鍵を TIP が自分で素通しにする」の印。キー要求の `t` は、TIP がキーを処理するときに
`QueryPerformanceCounter` から付けたミリ秒（TSF はキーの時刻を渡さない）。`mods` は小文字名の配列
（`["shift","ctrl","alt","win"]` の部分集合）。省略したら修飾キー自体の down/up で追跡する。

入力開始の `down` には、文書から取得した `left_context`（文字列、取得不能なら `null`）と、
同じ位置に反映した最新確定の `after_commit_seq`（番号、切断なら `null`、不明なら省略）を載せられる。
ブローカーは要求をそのまま転送する。採用条件は [変換仕様](CONVERSION.md) の「左文脈」を参照。

### ブローカーとエンジン（標準入出力）

- ブローカー → エンジン: `{"op":"open","sid":3}` `{"op":"close","sid":3}` `{"sid":3,"seq":17,"op":"down",…}`。
- エンジン → ブローカー: 準備ができたら `{"ready":true,"proto":1,"warnings":[…]}`。以後は要求 1 件に返事 1 件
  `{"sid":3,"seq":17,…}`。ready のあとで見つかった注意は `{"event":"warning","warning":"lm"}`（LM を読み込めなかった。1 回）。
- 1 セッションを標準入出力で直接動かす `python -m yuragi.ime.server` は、試験と評価用。

### 返事の項目

エンジンの返事（`yuragi/ime/server.py:snapshot`）。

| 項目 | 中身 |
|---|---|
| `composition` / `commit` | 変換中の表示 / この要求で確定した文字 |
| `converted` | 候補を開いた変換中か |
| `direct` / `pass_through` | 直接入力か / この down・up をアプリに渡すか |
| `fsm` / `n_tokens` / `timer` | 同時打鍵の判定の状態 / トークン数 / 次に `timeout` を送る時刻（無ければ null） |
| `segments` | 各文節・リテラルの `start/end`（トークン位置）、`surface/reading`、`literal/fixed`、`display_start/display_end`（表示のコードポイント位置。TIP が UTF-16 の位置に直す）。半開区間 |
| `focus` | 注目文節の `segments` 内の位置。無ければ -1 |
| `candidates` / `cand_index` / `candidate_kinds` | 注目文節の現在のページ（最大 9 件）/ ページ内の選択位置（無ければ -1）/ 各候補の `dictionary`・`kana`・`literal` など |
| `candidate_page` / `has_next_page` | 0 始まりのページ / 次のページの有無 |
| `predicting` | 候補窓が推測変換の候補か |
| `pending` | LM を待っていて、表示はまだ変わっていない |
| `error` | その要求で例外が出て、セッションを作り直した（「要求 1 件ごとの防壁」） |

### 互換の規則

更新後も、開いたままのアプリには古い DLL が残るので:

- 受け取る側は、**知らない項目を無視し、無い項目は既定値にする。** 項目の数や余分を検査しない。
- プロトコル 1 の中での変更は「項目を足す」だけ。意味を変える・消すことはしない。

## 4. ブローカー（`src/broker/`）

変換の中身は理解しない。メッセージは `sid` と `seq` を見て配るだけ。判断はすべて OS に依存しない
`broker_core` にある。

### 起動と終了

- サブシステムは WINDOWS（コンソールを持たない）。ウィンドウは通知用の非表示ウィンドウ 1 枚だけ。
- 二重起動は名前付きミューテックス `Local\yuragi-ime-broker` で防ぐ。取れなければ黙って終了コード 0。
- 起動したら `HKCU\Software\yuragi-ime\Tag` を読み、自分のタグと違えば（タグが無くても）黙って終了。
- 終了するのは: パイプで `quit` を受けたとき（インストーラ）、サインアウト。

### エンジンの起動のしかた

`CreateProcessW` で、次のとおり。

- 実行ファイルは `engine.json` に書いてある絶対パスの `python.exe` だけ。無ければ起動しない。
- フラグは `CREATE_NO_WINDOW`。同梱ランタイムの `python.exe` はランチャーを挟まないので、子も孫もコンソールを作らない。
- 環境変数は引き継がない。`CreateEnvironmentBlock` で利用者の既定の環境を作り、
  `PYTHONUTF8=1` `PYTHONIOENCODING=utf-8` `PYTHONNOUSERSITE=1` `HF_HUB_OFFLINE=1` を足し、
  `PYTHONPATH` `PYTHONHOME` を消す。
- 標準入力・標準出力は無名パイプ（ブローカーとの通信）。標準エラーは `logs\engine.log`
  （起動のたびに前の分を `engine.prev.log` に回す）。
- 「ブローカーが死んだら子も死ぬ」ジョブ（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）に入れる。孤児を残さない。
- 作業フォルダは `versions\<tag>\app`。

### 見張り

```
            ready 受信
 STARTING ───────────────► READY
    ▲  │                     │
    │  │ 終了（無応答で強制終了を含む）
    └──┴─────────────────────┘  ENGINE_EXIT_WINDOW_MS の間の ENGINE_MAX_EXITS 回目の終了なら ──► FAILED
                                                                  │
 STARTING ◄──────(利用者が「もう一度試す」／次のサインイン)────────┘
```

- **終了の検知**はプロセスのハンドルを待つ（ポーリングしない）。
- **無応答の検知**: エンジンに渡した要求の返事が `ENGINE_HANG_MS` 来なければ、エンジンを強制終了して
  「終了」と同じ扱いにする。エンジンは必ず即答する（LM 待ちは `pending` で即答）。
- 終了したら、すぐ起動し直す。FAILED に入ったら「通知」を 1 回出し、以後、自分からは何も起動しない。
  終了コードと `logs\engine.log` の最後の `fatal` 行は `broker.log` に残す。
- 利用者の「もう一度試す」（設定を変えたあとの再起動も同じ）は、数えた回数を 0 に戻して起動する。

### 使えない間の打鍵

- 預からない。状態が `ready` でない間に届いた要求には、すぐ `{"seq":n,"state":"starting"}`（FAILED 中は
  `"down"`）を返す。TIP はその打鍵からアプリへ素通しにする。
- hello に `passes:true` の無い接続（v0.1.2 の DLL。更新の前から開いているアプリに残る）は、準備中も打鍵を送り、
  `state` だけの返事を「食べた」とみなす。この接続には代わりに、エンジンの返事の形で
  `{"seq":n,"pass_through":true,"direct":<その接続の入力モード>}` を返し、打鍵をアプリへ通させる。
  入力モードは、その接続の最後の `set_direct` か、エンジンの返事の `direct` で覚えておく。
- エンジンが終了したら、処理中だった要求に `{"seq":n,"state":…}` を返し、全接続へ `{"event":"reset"}` を送る。
  新しいエンジンが `ready` になったら、接続ごとに新しいセッションを開く（かな入力で始まる）。
  TIP は `ready` を受け取ったとき、直接入力なら `set_direct` を送り直す。準備中に切り替えキーを押したときも、
  TIP は手元の入力モードだけを切り替えて、`ready` になってから送る。
- 注意（`lm`）はエンジンごと。エンジンを起動し直したら消し、新しいエンジンが言うものだけを持つ。

## 5. エンジン（`yuragi/`）

- 入口は `yuragi/engine.py`。起動直後に本物の標準出力を通信専用に確保し、`sys.stdout` は標準エラーに
  向け直す（ライブラリが `print` しても通信に混ざらない）。標準入力が閉じたら終了する。
- セッションは `sid` ごとに 1 つ。辞書・表・学習履歴・個人辞書は全セッションで共有する。
  要求は 1 本のスレッドで順番に処理する。LM は別スレッド（CONVERSION「言語モデル」）。
- **ネットワークに一切つながない。** LM は `local_files_only=True` で読む。

### 起動時の読み込み

利用者が触れるファイルは、壊れていても起動を止めない。プログラム自身のファイルが壊れていたら、はっきり止まる。

| ファイル | 壊れていたら | 利用者への知らせ |
|---|---|---|
| `config.json`（構文・値） | すべて既定値 | なし（ログに 1 行） |
| `personal_lexicon.jsonl` の壊れた行 | その行だけ飛ばす | 設定ウィンドウに件数 |
| `learning.jsonl` の壊れた行 | その行だけ飛ばす | 設定ウィンドウに件数 |
| `learning.jsonl` が読めない（他が開いている等） | 学習なしで動く（ファイルが変われば読み直す） | なし（ログに 1 行） |
| 辞書キャッシュが読めない | 消して、辞書から 1 回だけ作り直す（数分。その間は準備中） | 準備中の表示 |
| 辞書ファイルが無い（中身はインストール時に照合済み。起動時は在るかだけ見る） | **止まる** | 停止の通知 |
| LM のモデル・torch が読めない | LM なしで動く | 設定ウィンドウの注意（`lm`） |
| Python のモジュールが読めない | **止まる** | 停止の通知 |

辞書キャッシュは、**辞書マニフェストのハッシュを名前にして**、一時ファイルに書いてから置き換える。
古い辞書のキャッシュを使うことも、書きかけが残ることも起こりえない。

> **注意**: 辞書の読み込みで、欠けたファイルや読めない行を黙って飛ばさない。辞書の一部（`suffix.txt`）が
> 欠けたまま作られたキャッシュが、変換の質を少し落としたまま気づかれずに使われ続けたことがある。

### 暖機

`ready` を出す前に、ダミーの変換を 1 回実行する。利用者の最初の打鍵が遅くならない。

LM はそのあとワーカーで読み込み、使い始める前に同じダミーの入力を 1 回 LM で変換する（読みの選択と zenz の確認）。
読み込みが済んだあとの最初の変換から、LM も定常状態の速さになる。かかった時間は `engine.log` に
`warm-up conversion … ms` と残す。

### 要求 1 件ごとの防壁

要求処理ループは、要求 1 件の処理全体を 1 つの `try` で囲む。例外が出たら:

1. `logs\engine.log` に、例外の型と発生箇所（ファイル名・行番号・関数名）を書く。入力した文字は書かない。
2. そのセッションを作り直す。
3. `{"sid":…,"seq":…,"error":true, …作り直したあとの状態… }` を返す。

エンジンは落ちず、TIP は見えている文字をそのまま確定する。防壁はここ 1 か所だけに置き、変換の中身
（`session.py` 以下）には置かない。

### 入力の長さ

変換中の入力は `MAX_TOKENS` まで。達したら、文字キーは受け取るが黙って何も変えない。
変換時間は長さに比例するので、1 回の要求の所要時間に上限が付く。

### 止まるときの理由

起動できないと判断したら、標準エラーに `fatal <英数字の短い説明>` を 1 行書いて、終了コード 1 で終わる
（`program-files-unreadable`、`dictionary-missing`、`dictionary-unreadable`、`cache-not-written`）。
ブローカーはこの行と終了コードを `broker.log` に残す。利用者への知らせは原因によらず「通知」の 1 種類。

### 学習履歴のファイル

記録の形式と変換への効き方は CONVERSION「学習」。ここではファイルの扱いだけを決める（`learning.py`）。

1. **自分が書いた分は読み直さない。** 追記したら、同じ行をメモリ上の索引にも足し、
   書いたあとのファイルの大きさと更新時刻を覚える。
2. **他のプログラム（設定ウィンドウ）が書いたら、全体を読み直す。** 変換のたびにファイルの大きさと
   更新時刻を見て、覚えているものと違えば、最初から読み直す。
3. **整理は起動時に 1 回。** 行数が「生きている記録の 2 倍」かつ `COMPACT_MIN_LINES` を超えていたら、
   生きている記録だけを一時ファイルに書いて置き換える。生きている記録とは、抑制されておらず、
   同じ（読み・表記）の中で最新のもの。
4. **読めない・書けないときは**、ログに 1 行書き、その回は学習なしで続ける。変換は止めない。
5. 行ごとの検査は、「JSON として読めて、必要な項目がある」だけ。

学習の入／切は `config.json` の `learning` で決める。ファイルは最初の確定で作る。

## 6. TIP（`src/tip/`）

TSF とのやりとり（キーの受け取り、変換中の文字の描画、表示属性、候補ウィンドウ、言語バー、トグルキー）と、
ブローカーとの接続（`BrokerLink`）。判断のうち TSF に依存しないもの（返事の解釈、食べるかどうか、
返事の順序、状態と表示）は `src/tip/tip_logic.h` にある。エンジンの起動・見張り・再試行、Python の探索と起動、
設定ウィンドウの起動は持たない。ログは `tip.json` の `log:true` のときだけ書く。

> **注意**: TIP の中で入力を待たない。`ActivateEx` で辞書の準備などを待つと、Windows 11 の
> TextInputHost が止まり、すべての IME が使えなくなる。

### 接続

- `Tip` 1 個につき、パイプ 1 本と読み取りスレッド 1 本。
- 読み取りスレッドは、届いた 1 行ごとに解析して、TIP のメッセージ専用ウィンドウへ `PostMessage` するだけ。
  待つのは「パイプの読み取り」「停止の合図」「接続の合図」の 3 つで、時間で回るものは無い。
- 接続を試すきっかけは 3 つだけ: `ActivateEx`、かな入力モードで打鍵があったとき、利用者がメニューで
  「もう一度試す」を選んだとき。前回の試みから `CONNECT_MIN_INTERVAL_MS` 以内なら試さない。
- 書き込みは UI スレッドから。重ね合わせ I/O で、`KEY_BUDGET_MS` 以内に書けなければその打鍵は素通し。

### ブローカーを起動する条件

パイプが無かったとき、**次の全部が成り立つ場合に限り**、ブローカーを起動する。条件に合わないプロセスは接続するだけ。

1. `HKCU\Software\yuragi-ime\Tag` が、この DLL のタグ（ビルド時に埋め込む）と同じ。
   ——アンインストール済み・更新済みの古い DLL は、ここで必ず止まる。
2. 保守中の印 `Local\yuragi-ime-maintenance` が無い。——インストーラの作業中は誰も起動しない。
3. このプロセスが、サンドボックスの中でなく、管理者権限でもない（整合性レベルが「中」）。

回数は数えない。ブローカーの二重起動防止と、接続を試す間隔で足りる。

実行ファイルは**この DLL と同じフォルダ**の `yuragi-broker.exe`。フラグは
`CREATE_NO_WINDOW | CREATE_BREAKAWAY_FROM_JOB`、ハンドルは引き継がない、環境は `CreateEnvironmentBlock` で
作ったもの。起動に失敗したら（ジョブからの離脱が許されない環境を含む）、その場ではやり直さない。
起動したら、パイプが現れるのを最大 `BROKER_WAIT_MS` 待つ（100ms 間隔）。

通常はサインイン時に Run キーでブローカーが起動しているので、この経路は「ブローカーが何かで消えた」ときの回復用。

### 打鍵の処理

次のときは食べず、何も送らない: キーボードが無効、IME が閉じている、フォーカスのある文書が無い、
パスワード欄（切り替えキーも食べない）、直接入力、ブローカーにつながっていない、エンジンが `ready` でない
（準備中の切り替えキーだけは食べて、手元の入力モードを切り替える。「使えない間の打鍵」）。
変換中の文字が無いときの Enter・BS・Esc はアプリへ渡す。それ以外は:

1. `OnTestKeyDown`: 手元の状態だけで「食べるか」を答える（通信しない）。
   **返事を待っている要求が 1 件でもあれば「変換中」とみなす**——後から来た Enter や BS が先にアプリへ抜けない。
2. `OnKeyDown`: 打鍵の時刻 `t` を記録し、かな入力の開始時だけ同期の読み取りセッションで文書の左文脈を取得する。
   通し番号 `seq` を付けて要求を送り、`t` から `KEY_BUDGET_MS` の期限までその番号の返事を待つ。
   - **間に合った** → 同期の編集セッションで画面に反映し、返事に従って食べる／通す。
   - **間に合わなかった** → 1 の判定どおりに食べて、すぐ戻る。接続は切らない。画面も触らない。
     返事は後で読み取りスレッドから届き、非同期の編集セッションで反映する。
3. 返事は必ず `seq` の順に反映する。前の返事がまだなら、届いても待たせる。
4. 返事が `{"seq":n,"state":"starting"}`（または `"down"`）なら、その打鍵はアプリへ通し、以後は状態が
   `ready` に戻るまで送らない。

### 見えている文字の確定

次のどれかを受け取ったら、変換中の文字列があれば**その表示のまま確定して**（文字は消さない）、手元の状態を初期化する。

- `{"event":"reset"}`（エンジンが終了した）
- 返事の `"error":true`
- 返事・通知の `state` が `down`
- パイプが切れた（ブローカーが消えた）
- 入力モードの切り替え（エンジンの中の入力は捨てられる）

文字を消してよいのは、利用者が Esc を押したときと、フォーカスが移ってアプリが変換を打ち切ったときだけ。

フォーカスの移動、アプリによる変換終了、入力モードの切り替え、切断では、古い応答と未適用の編集要求を破棄する。
同じ入力欄に戻っても、古い応答は反映しない。

### タイマー

- 常時タイマーは持たない。返事の `timer`（同時打鍵の判定期限、LM 待ちの次の問い合わせ時刻）があるときだけ、
  その時刻に 1 回鳴るタイマーを掛ける。鳴ったら `timeout` を送る。
  タイマーを掛け直すたびに新しい ID を使い、取り消したタイマーの通知が届いても無視する。
- 候補ウィンドウの位置は、TSF の配置変更通知（`ITfTextLayoutSink::OnLayoutChange`）で直す。

### パスワード欄

入力欄の種類（`IS_PASSWORD`・`IS_NUMERIC_PASSWORD` ならパスワード欄）は、フォーカスが移ったときに 1 回
調べて覚える（読み取り専用の編集セッション）。同期で調べられなければ非同期で頼み、答えが出るまでは
素通しにする。「選択範囲が取れない」「入力欄の種類が取れない」は、パスワード欄の証拠として扱わない。
左文脈の本文を読むときは入力欄の種類を再確認する。入力スコープの照会に失敗した場合は本文の取得を見送る。

## 7. インストール・更新・アンインストール

### 共通の仕組み

- **取得**: 公式の場所（GitHub / python.org / PyTorch / PyPI / HuggingFace）からだけ取得する。版は固定し、
  ハッシュを照合する。
- **README の 1 行の形**: 「前回の残り（`%TEMP%\yuragi-setup.ps1`）を消す → 取得 → 取得できたとき（`$?`）だけ実行」。
  取得に失敗したとき、前回取得した古いスクリプトは走らない。Windows PowerShell 5.1 には `&&` が無いので
  `if ($?)` で書く。アンインストールの 1 行と、setup が最後に表示する 1 行も同じ形。
- **保守中の印**: `setup.ps1` と `uninstall.ps1` は、最初に（管理者権限でない側で）ミューテックス
  `Local\yuragi-ime-maintenance` を作って持つ。スクリプトが終われば、成功でも失敗でも強制終了でも、
  Windows が自動で消す。この印がある間、TIP はブローカーを起動しない
  （動いているブローカーには、スクリプトが `quit` を送る）。
- **管理者権限で行うのは 3 つだけ**（UAC は 1 回）: ①`Program Files` へのファイルの配置、
  ②`regsvr32` による登録／解除、③古い版の `Program Files` 側の削除。
  これは `packaging/elevated.ps1` にまとめ、**Python は管理者権限で動かさない。**
  呼び出しは `-EncodedCommand`（空白・引用符・日本語を含むパスも崩れない）。結果は終了コードと、
  利用者側が読める結果ファイルで返す。
- **登録の確認**: 登録／解除のあと、`elevated.ps1` がレジストリを読み返して確かめる（1 か所だけ）。
  確かめられなければ失敗として扱う。
- **使用中のファイル**: 消せないファイル（アプリが読み込んでいる DLL）はそのまま残し、次の実行で消す。
  版ごとのフォルダなので、残っても邪魔にならない。`DllUnregisterServer` は、どれか 1 つでも失敗したら失敗を返す。
- **言語一覧への追加・削除**（`InstallLayoutOrTip`）は利用者ごとの設定なので、管理者権限でない側で行う。

### インストールと更新（同じ手順、`setup.ps1`）

README の 1 行で `setup.ps1` を取得して実行する。管理者ではない普段の PowerShell から実行する
（管理者権限が要る段 5 で確認が 1 回出る）。

| 段 | すること | ここで失敗したら |
|---|---|---|
| 1 | 保守中の印を立てる | — |
| 2 | `staging\<tag>\` に取得・照合・展開。足りない共有物（ランタイム・辞書・モデル）だけ `shared\` に作る。共有物は「作りかけの名前で作って、完成したら改名」。ランタイムは Python の埋め込み版に、リリースに添えた同じ版の tkinter 一式（`python-<版>-tkinter-amd64.zip`）を重ね、torch・依存・tkinter とあわせて読み込めることを確かめる。torch は、`nvidia-smi` で CUDA 対応の GPU とドライバが見つかれば GPU 版（`cu128`／`cu126`。ディスクの空きが 10GB 以上のとき）、無ければ CPU 版。GPU 版のランタイムは名前に `-cu128` などが付く別の共有物 | 何も変わっていない。旧版が動き続ける。やり直せば続きから |
| 3 | **本物のブローカーで試運転**: `yuragi-broker.exe --selftest <staging の engine.json>`。エンジンを実際に起動し、変換を 1 回行って終了コードを返す。利用者のデータは使わない | 同上 |
| 4 | `staging\<tag>` を `versions\<tag>` へ改名（一瞬）。`versions\<tag>` が既にあれば脇へ寄せる。それが入っている版（Tag が同じ）なら同じ版の入れ直しで、先にそのブローカーを止める。違えば前回の途中の残りで、動いている版には触らない | 同上 |
| 5 | 管理者権限: `Program Files\yuragi-ime\<tag>\` に配置、登録を新しい DLL に付け替え、読み返して確認 | 旧版の登録のまま。旧版が動き続ける |
| 6 | 旧ブローカーに `quit`。`HKCU\…\Tag` と Run キーを新しい版に書き換え、言語一覧に追加 | — |
| 7 | 印を下ろし、新ブローカーを起動して `ready` を待って確認（最大 60 秒） | 理由を表示。次のサインインでも起動を試みる |
| 8 | 旧版の片付け: `versions\` と `shared\` の使われていないもの。`Program Files` 側の旧版は 5 の管理者権限の中で消す（使用中のものは残す） | 片付けの失敗はインストールの失敗にしない。次回の setup がまた試す |

- 4 までは、動いている版に一切触らない。5〜7 は数秒。
- 更新のあと、開いたままのアプリには旧 DLL が残る。旧 DLL は「ブローカーを起動する条件」の 1 で何も起動せず、
  新ブローカーに接続する（「互換の規則」によりそのまま動く）。
- `staging\` は自分の作業場なので、いつでも消して作り直してよい。
- 取得先に届かないネットワークでは、届かなかった取得の段で止まる。
- 署名なしの DLL とブローカーは、Smart App Control やウイルス対策に止められ得る。止められた場合は、
  試運転（段 3）か起動の確認（段 7）が理由を表示して止まる。
- ARM 版の Windows では、setup が最初に「ARM 版 Windows には対応していません。」と表示して止まる。

### アンインストール

リリースの `uninstall.ps1` は入口（`packaging/uninstall-entry.ps1`）で、HKCU の Tag で入っている版を見つけ、
その版の本体（`versions\<tag>\app\packaging\uninstall.ps1`）を、引数（`-RemoveData` `-Yes`）をそのまま渡して呼ぶ。
Tag が無ければ「インストールされていません」と表示して終わる。本体がすること:

1. 保守中の印。
2. Run キーを消し、言語一覧から外す。
3. ブローカーに `quit`（エンジンも終了する）。
4. 管理者権限: 登録解除、読み返して確認。`Program Files\yuragi-ime\` を削除。使用中のファイルは残す。
5. HKCU の `Software\yuragi-ime`（Tag）と、言語一覧から外したときに Windows が書く
   TSF の利用者設定（`SOFTWARE\Microsoft\CTF\TIP\{CLSID}`）を削除。`%LOCALAPPDATA%\yuragi-ime\` を削除。
   Tag は登録解除のあとで消すので、途中で止まっても、入口からやり直せる。
6. 結果を表示する。使用中のファイルが残ったときは「登録は外れているので使われません。アプリを閉じたあとに
   削除できます」と伝える。サインアウトや再起動を求めない。

`~\.yuragi-ime\`（学習履歴・個人辞書・設定）は残す。消すのは `-RemoveData` を付けたときだけで、
そのときも消す前に場所と大きさを表示する（`-Yes` で確認を省く）。

### 開発時（`dev-build.ps1`・`dev-register.ps1`）

- `src\tip\dev-build.ps1`: TIP とブローカーを Release でビルドして試験し、`dist\yuragi_tip.dll` と
  `dist\yuragi-broker.exe` を作る（管理者権限・登録なし）。リリースのワークフローもこれを使う（CI は cmake を直接呼ぶ）。
- `src\tip\dev-register.ps1 [-Python <python.exe>]`: タグ `dev` として登録する（UAC 1 回）。
  `HKCU\…\Tag = dev`、`versions\dev\engine.json` はリポジトリを指し、エンジンは指定の Python で動く。
  開発登録は `--require-lm` を付けて起動する。設定が `lm_rescore: false` でも zenz を暖機し、成功してから
  `ready` を返す。モデルの読み込みや暖機に失敗すると `fatal lm-unavailable` で終了する。
  DLL とブローカーは `dist\` から読み込む（開発機に限り `Program Files` 配置を省く）。DLL は
  `dist\yuragi_tip-a.dll`、`-b.dll`、… のうち、登録中でも使用中でもない最初のものにコピーして登録するので、
  古い DLL を読み込んだアプリを閉じなくても入れ直せる。
- 外すときは、製品版と同じ `packaging\uninstall.ps1`（`dev-register.ps1` が `dist\` に置く `elevated.ps1` を使う）。

## 8. 利用者に見えるもの

普通の利用者は「ゆ」と「Y」以外のものを見ない。見せるのは、利用者が何かしないと直らないときだけで、
何が起きたか・文字は無事か・どうすればよいか、を 1 つの文で言う。どれもフォーカスを取らない。
利用者向けの説明は [USAGE.md](USAGE.md)。

### 状態

| 状態 | タスクバー | 打鍵 | いつ |
|---|---|---|---|
| 通常 | 「ゆ」／「Y」 | 変換される | ほぼ常に |
| 準備中 | 「ゆ」／「Y」（薄く） | そのまま通る（直接入力と同じ）。切り替えキーは効く | サインイン直後の数秒、エンジンの起動し直し中 |
| 停止 | 「!」 | そのまま通る | 自動で直せなかったとき |
| 対象外 | 「Y」 | そのまま通る | 更新作業中、この利用者には未インストール、サンドボックス・管理者のアプリでブローカーが無い |

### 小さな表示

候補ウィンドウと同じ作り（`WS_EX_NOACTIVATE`。フォーカスもクリックも取らない）で、文字入力位置の下に 1 行だけ出す。
出すのは 1 種類だけ。

| いつ | 文言 | 消える条件 |
|---|---|---|
| 停止中に、かな入力のつもりで文字キーを押した（フォーカスごとに 1 回） | `日本語変換が止まっています。タスクバーの「!」を右クリックしてください` | `NOTICE_SHOW_MS` |

### 通知

ブローカーが、停止に入ったときに 1 回だけ、Windows の通知（`Shell_NotifyIcon`。フォーカスを取らない）で出す:

> **ゆらぎ: 日本語変換が止まりました**
> 入力済みの文字はそのまま残っています。ここを押すと、もう一度試せます。

押すと、ブローカーがネイティブのダイアログ（`TaskDialogIndirect`。Python が壊れていても出せる）を開く。
本文は「変換エンジンが繰り返し止まったか、反応しなくなりました。「もう一度試す」で起動し直します。
直らなければ、インストールの1行をもう一度実行してください。」、ボタンは `もう一度試す`
`記録のフォルダを開く` `閉じる`。原因（終了コード、`fatal` 行）は `broker.log` に残す。

起動はできている軽い異常（LM が使えない）は通知せず、`broker.log` と設定ウィンドウの「状態」タブの「注意」に出す。
止まったことは `logs\notices.log` にも残す（設定ウィンドウの「最後に止まった理由」）。

### メニュー

タスクバーの「ゆ」「Y」の右クリック:

| 状態 | 項目 |
|---|---|
| 通常 | `直接入力に切り替え`／`かな入力に切り替え`、`設定を開く` |
| 準備中 | `（変換の準備をしています）`（押せない）、`設定を開く` |
| 停止 | `もう一度試す`、`設定を開く` |

設定ウィンドウは TIP が起動するのではなく、ブローカーに `open_admin` を頼む（ブローカーが `pythonw.exe` で起動）。
設定ウィンドウの「状態」タブに、ブローカーとエンジンの状態・注意・最後に止まった理由・学習履歴の行数を出す。
設定を変えたあとの「変換エンジンを再起動」は、ブローカーへの `retry` と同じ仕組みで行う。

## 9. 実地試験

Windows サンドボックスか仮想マシンで、各操作の間、新しく生まれたプロセスと新しく現れた最上位ウィンドウを記録する。
メモ帳・ブラウザ・エクスプローラを開き、IME を選んで打鍵した状態から始める。

| # | 操作 | 期待 |
|---|---|---|
| 1 | インストール → IME を選ぶ → かなを打って変換 | 変換できる。常駐はブローカー 1・エンジン 1。ウィンドウ 0 |
| 2 | 変換の途中でエンジンをタスクマネージャーで終了し、打ち続ける | 見えていた文字が残る。起動し直す間の打鍵はそのまま（英字で）入り、数秒後から変換される。ウィンドウ 0 |
| 3 | エンジンを 10 分以内に 3 回終了 | 3 回目で「!」と通知 1 回。以後、起動 0 回 |
| 4 | メニューの「もう一度試す」 | 戻る |
| 5 | ブローカーをタスクマネージャーで終了し、打鍵する | 数秒で戻る |
| 6 | `config.json` を壊してサインインし直す | 変換できる（既定の設定で） |
| 7 | 辞書ファイルを 1 つ消してサインインし直す | 「!」と通知 1 回。起動はちょうど 3 回 |
| 8 | **アプリを開いたまま**更新 | 終わる。開いていたアプリでそのまま打てる。学習が残る |
| 9 | 更新の途中（取得中）で回線を切る／setup を強制終了 | 旧版で打てる。やり直すと終わる |
| 10 | **アプリを開いたまま**アンインストール | 終わる。60 秒、プロセス 0・ウィンドウ 0。学習履歴は残っている |
| 11 | スタートメニューの検索欄、「設定」、管理者として開いたメモ帳で打鍵 | 変換できる、または黙って素通し。どちらでもプロセスの起動 0 |
| 12 | 初回インストールの途中で回線を切る → やり直す | 手で何も消さずに終わる |
| 13 | 再起動してサインイン直後に打鍵 | 準備中（薄い「ゆ」）の間はそのまま入り、準備ができたら変換される |

## 10. 定数

| 名前 | 値 | 場所 | 意味 |
|---|---|---|---|
| `KEY_BUDGET_MS` | 200 | TIP | 打鍵 1 回で UI スレッドが待つ上限 |
