# Mac の日本語入力と Windows（MS-IME・ゆらぎ）のキー操作の違い

Mac の日本語入力に慣れた人が Windows でゆらぎを使うときに、何がどれだけ違うかの整理。
Mac 側は実機で確かめた動き（[macos.md](macos.md) §10、全表は [macos-table.md](macos-table.md)）、
MS-IME 側は実機の表（[ms-ime.md](ms-ime.md) §1.5）、ゆらぎ側は今の既定のキー割り当て（`yuragi/data/keymaps/ms-ime.json`、局面とコマンドは [KEYBIND.md](../KEYBIND.md) §3）。

- Mac は「日本語 - ローマ字入力」の既定の設定（ライブ変換オフ、Windows風オフ、US 配列）。ライブ変換は §6。
- キーの名前は Windows に合わせる（Mac の Delete は Backspace、fn＋Delete は Delete、Return は Enter、Option は Alt）。Mac の Command のキーは IME を通らないので扱わない。
- 「入力中」「変換中」などの状態の名前は [KEYBIND.md](../KEYBIND.md) §3.1 の局面に合わせる。

---

## 1. 要約

Mac から来た人がつまずきそうな順。

| # | 違い | Mac | MS-IME・ゆらぎ | 度合い |
|---|---|---|---|---|
| 1 | 割り当ての無いキー（入力中・変換中） | **食べて何もしない**。入力は残る | 確定してアプリに通す | 概念 |
| 2 | 候補ウインドウの Enter | **選ぶだけ**（窓を閉じ、次の文節へ）。確定は 2 回目 | 1 回で全部確定 | 概念 |
| 3 | 変換中の Backspace | 末尾 1 字を消して、**残りを確定** | 末尾 1 字を消して、文節内入力（確定しない） | 粒度 |
| 4 | 変換中の Esc | **全部の文節**を読みに戻す | 注目文節だけ読みに戻す（全部は Shift+Esc） | 粒度 |
| 5 | Ctrl+英字 | J/K/L/; が字種、N/P が候補、B/F が文節、I/O/W が伸縮 | U/I/O/P/T が字種、K/L が伸縮、N が先頭文節の確定 | キーの衝突（§4） |
| 6 | F8 | 半角英字 | 半角カタカナ | キー |
| 7 | 文節の伸縮のあと | すぐ変換し直す | 読みで見せ、Space で変換 | 粒度 |
| 8 | 予測候補 | 数字で選べない。Backspace は 1 字消して確定 | 数字で選ぶ。Backspace は予測をやめる | 粒度 |
| 9 | 確定の取り消し・再変換 | Ctrl+Delete（直前の確定）、Ctrl+Shift+R・かな 2 回（選んだ文字） | 新 MS-IME は変換キー（JIS）で再変換。確定取り消しは無い。**ゆらぎはどちらも無い** | 機能 |
| 10 | IME のオン/オフ | 入力ソースの切り替え（Ctrl+Space、英数/かなキー）。オン/オフの考えが無い | Alt+`` ` ``、半角／全角で開閉。ゆらぎは Mac の JIS キーボードの かな / 英数キー（LANG1 / LANG2）でも、ひらがな / 直接入力にする | 概念（かな・英数キーは同じ） |
| 11 | ライブ変換 | ある（設定でオン） | 無い | 機能 |
| 12 | 候補ウインドウのタブ | Tab で 標準／読み／部首／名前／記号 を替える | Tab は表の形に広げる（ゆらぎは何もしない） | 機能 |

## 2. 度合いの分け方

| 度合い | 意味 | ゆらぎで Mac 風にするには |
|---|---|---|
| 同じ | 同じキーで同じ動き | 何もしない |
| キー | 同じ操作が別のキーにある | プリセットの行を書くだけ |
| キーの衝突 | 同じキーが両方で別の操作を持つ | プリセットの行で済むが、MS-IME 風と同時には持てない |
| 粒度 | 操作の考えは同じで、効く範囲・段階・確定するかが違う | コマンドを足す（今あるコマンドの変種） |
| 概念 | 状態や操作の考え方そのものが違う | 仕組みを足す（局面の動き、既定の扱いを変える） |
| 機能 | 片方にしかない機能 | 機能を作る |

## 4. 同じキーで意味が違うもの（衝突）

Mac 風と MS-IME 風を 1 つのプリセットで両立できないキー。Mac 風のプリセットを作るなら、どちらを取るかを決める。

| キー | Mac | MS-IME・ゆらぎ |
|---|---|---|
| Ctrl+I | 入力中は確定、変換中は文節を縮める | カタカナ（F7） |
| Ctrl+K | カタカナ | 入力中はカーソル左、変換中は縮める |
| Ctrl+L | 全角英字 | 入力中はカーソル右、変換中は伸ばす |
| Ctrl+J | ひらがな | 確定して通す |
| Ctrl+; | 半角英字 | ゆらぎは割り当て無し（確定して通す） |
| Ctrl+A | 半角英字 | 先頭へ（入力中）・先頭の文節へ（変換中） |
| Ctrl+F | カーソル右・次の文節 | 末尾へ・末尾の文節へ |
| Ctrl+B | カーソル左・前の文節 | 予測では Web で検索（ゆらぎは何もしない）。ほかはゆらぎに割り当て無し（確定して通す） |
| Ctrl+N | 予測に入る・次の候補・窓を開く | 末尾へ（入力中）・先頭の文節を確定（変換中） |
| Ctrl+P | 前の候補・窓を開く | 全角英字（F9） |
| Ctrl+O | 文節を伸ばす | 半角カタカナ（F8） |
| Ctrl+W | 文節を伸ばす | 確定して通す |
| Ctrl+R / Ctrl+V | 変換・前 / 次のページ | 確定して通す |
| Ctrl+Q | 入力を捨てて制御文字を確定（不具合とみる。真似ない） | 確定して通す |
| Ctrl+Z | 何もしない | 注目文節を読みに戻す |
| Ctrl+Delete | 確定の取り消し | 学習を忘れる（候補ウインドウ） |
| F8 | 半角英字 | 半角カタカナ |
| Tab（変換中） | 確定 | 確定して Tab を通す |
| Tab（候補ウインドウ） | 窓のタブを替える | 表の形に広げる（ゆらぎは何もしない） |
| Space（予測） | 予測をやめて読みを変換 | 次の候補（ゆらぎ） |
| ↑ / ↓（変換中） | 窓を開く | 確定して通す |
| Enter（候補ウインドウ） | 選ぶだけ | 確定 |

同じキーで同じ意味のもの: Ctrl+H（前の字を消す）、Ctrl+S / Ctrl+D（左右）、Ctrl+M（確定）、Ctrl+E / Ctrl+X（予測・候補の上下に近い）、F6・F7・F9・F10、Home・End、Shift+←/→（伸縮）。

## 5. 割り当ての無いキーの扱い（概念の違い）

- Mac は、入力中・変換中に IME が使わないキー（Ctrl+C、Ctrl+T、Alt+矢印、Command+矢印など）を**食べて何もしない**。入力は残る。
  アプリにキーを渡すのは Esc を押し切ったあと（入力が無いとき）だけ。
- MS-IME とゆらぎは、割り当ての無いキーで**確定してアプリに通す**（[KEYBIND.md](../KEYBIND.md) §4.3 の `commit_and_pass`）。
- Mac から来た人は「入力中にうっかり押したキーで確定してしまう」ことに驚くかもしれない。逆に、Ctrl+C などで確定してコピーする Windows の使い方は Mac には無い。
- ゆらぎで Mac 風にするなら、プリセットごとに「割り当ての無いキーの既定」を `commit_and_pass` か `noop` かで選べるようにする（今は `commit_and_pass` に決めてある）。

## 6. ライブ変換（Mac のみ）

Mac には、打つそばから変換して見せるライブ変換がある（設定でオン/オフ。macOS の初期値はオン、この Mac はオフにしてあった）。MS-IME とゆらぎには無い。
キーの動きは [macos.md](macos.md) §10.7。通常の変換と違うところ:

- 入力中から読みでなく変換した文字が見えている。Space・←・→・↑・↓ で「文節を選ぶ状態」に入る（← は最後の文節、ほかは先頭の文節）。← でカーソルは動かない。
- Esc は最後の文節から 1 段ずつ読みに戻す。Backspace は読みの末尾 1 字を消すだけで、確定しない。
- Enter は 1 回で確定する（候補ウインドウが開いていないとき）。

ライブ変換に慣れた人は「Space を押さずに打ち続け、Enter で確定」する。ゆらぎで似た使い心地を出すには、入力中に自動で変換結果を見せる仕組みが要る（予測候補の自動表示とは別）。

## 7. ゆらぎで Mac 風のプリセットを作るときに要るもの

| 要るもの | 中身 | 区分 |
|---|---|---|
| キーの行 | §3 の「キー」の行（Ctrl+J/K/L/;、Alt+Z/X/C/A/S、Ctrl+N/P、Ctrl+B/F、Ctrl+I/O/W/Q の伸縮、Ctrl+R/V のページ、Alt+Space など） | 利用者のキー設定（段 3。作ってある）で今でも書ける。プリセットにするのは段 4 |
| Esc で全部の文節を読みに戻す | 今の `cancel_conversion`（変換をやめて入力中に戻る）で足りる | プリセットだけ |
| 変換中の Backspace で末尾を消して確定 | `delete_last_and_commit`（新しいコマンド） | 粒度 |
| 候補ウインドウの Enter で選ぶだけ | `accept_candidate`（窓を閉じ、次の文節へ。最後の文節ならそのまま） | 粒度 |
| 伸縮してすぐ変換 | `segment_shrink`／`segment_expand` の、読みにせず変換し直す変種（`resizing` に入らない） | 粒度 |
| 予測の Backspace・Space | Mac の動きに合わせたコマンド（末尾を消して確定、予測をやめて変換）。数字で選ばない | 粒度 |
| 窓を開くだけ（↑ / ↓） | `open_candidates`（候補を変えずに窓を開く） | 粒度 |
| 割り当ての無いキーの既定 | プリセットごとに `noop` を選べるようにする（§5） | 概念 |
| 入力中の後ろの字を消さない | Delete を `noop` にするだけ | プリセットだけ |
| 確定の取り消し（Ctrl+Delete） | `undo_commit` を作る。TSF で直前の確定範囲を読みに戻す | 機能 |
| 再変換（Ctrl+Shift+R） | `reconvert` を作る（選んだ文字を変換し直す） | 機能 |
| 候補ウインドウのタブ（読み・部首など） | 作らない候補（ゆらぎの辞書の作りに依る） | 機能 |
| ライブ変換 | §6 | 機能 |
| 日本語 ↔ 英字の切り替え | Ctrl+Space を `ime_toggle` に割り当てる案。ただし Windows では Ctrl+Space をアプリや中国語 IME が使うことがある | 概念 |

真似ないもの: Ctrl+Q・Home（予測）・End（予測）で制御文字を確定する動き（日本語入力プログラムの不具合とみる）、F8 の半角英字（F10 と重なるので、半角カタカナのままでよい）。

## 8. 確かめていないこと

- Mac: Caps Lock（調べた Mac では無効）、JIS キーボードの本物の英数・かなキー、かな入力、ほかのアプリ（ブラウザ、Electron）での違い、F6・F7 を続けて押したときの循環。
- MS-IME: 候補ウインドウで番号を選んだあと確定まで行くか（[ms-ime.md](ms-ime.md) §1.4 は「選ぶ」とだけ書く）。
- 再変換・確定の取り消しは、Mac の試験アプリが選択範囲と置き換え範囲を最小限にしか扱わないので、ふつうのアプリ（テキストエディット）では動きが違うかもしれない。
