# Microsoft IME のキー操作とカスタマイズ

Microsoft IME の既定キーと、キー割り当てを変える仕組みをまとめる。対象は 2 つ。

- **新 MS-IME**: Windows 10 2004 以降と Windows 11 の既定。
- **以前のバージョンの MS-IME**（以下、旧 IME）: 新 IME の互換性設定でオンにして使う。

出典は末尾の「出典」の略号で示す。

---

## 1. 新 MS-IME の既定キー

### 1.1 IME オン/オフ・入力モード（日本語キーボード 106/109）

| キー | テンプレート「Microsoft IME」 | テンプレート「ATOK」 | 出典 |
|---|---|---|---|
| 半角/全角 | 日本語入力のオン/オフ | 日本語入力のオン/オフ | S1, S2 |
| 英数 (Caps Lock) | ひらがなモードと英数モードを切り替え | 同左 | S1, S2 |
| ひらがな（カタカナひらがなローマ字） | ひらがなモードに入る | ひらがなモードと英数モードを切り替え | S1, S2 |
| Alt+ひらがな | かな入力とローマ字入力を切り替え（全般の「Alt+カタカナひらがなローマ字キーでかな/ローマ字入力を切り替える」がオンのとき） | 同左 | S1, S2 |
| Shift+ひらがな | カタカナモードに入る | 同左 | S1, S2 |
| 変換 | 再変換 | 日本語入力のオン/オフ | S1, S2 |
| Shift+変換 | 資料に無い | 再変換 | S1, S2 |
| Ctrl+変換 | IME のコンテキストメニュー（右クリックメニュー）を開く | 資料に無い | S1, S2 |
| 無変換 | ひらがな → 全角カタカナ → 半角カタカナ を順に切り替え | ひらがなモードと半角英数モードを切り替え | S1, S2 |
| Ctrl+無変換 | 資料に無い | ひらがな → 全角カタカナ → 半角カタカナ を順に切り替え | S1, S2 |
| Shift+無変換 | 半角英数と全角英数を切り替え | ひらがな → 全角英数 → 半角英数 を順に切り替え | S1, S2 |
| ImeOn（あ）※ | ひらがなモードに入る | 同左 | S1, S2, S4 |
| Alt+ImeOn ※ | かな/ローマ字入力の切り替え（既定はオフ。上と同じ設定が要る） | 同左 | S1, S4 |
| Ctrl+ImeOn ※ | 再変換（S4 の表では「入力/変換済み文字なし」の状態のときだけで、他の状態ではなし） | 同左 | S1, S4 |
| Shift+ImeOn ※ | 全角カタカナモードに入る | 同左 | S1, S4 |
| ImeOff（A）※ | 半角英数モードに入る | 同左 | S1, S4 |
| Ctrl+ImeOff ※ | ひらがな / 全角カタカナ / 半角カタカナ を順に切り替え（S4 では入力文字があるときだけ） | 同左 | S1, S4 |
| Shift+ImeOff ※ | 全角英数を 小文字 → 全部大文字 → 先頭だけ大文字 の順に切り替え（S4 では入力文字があるときだけ） | 同左 | S1, S4 |

※ ImeOn / ImeOff は特定の日本語ハードウェアキーボードにだけある。Windows 10 1903 以降が対象 [S4]。

- ImeOn: スペースバーの右。HID LANG1 → `VK_IME_ON (0x16)`。
- ImeOff: スペースバーの左。HID LANG2 → `VK_IME_OFF (0x1A)`。

### 1.2 どのキーボードでも使えるショートカット（US 配列 101/102 を含む）

S1 の「English keyboard (101/102 key)」タブの表。S2 ではこのタブの名前は「日本語キーボード (101/102 キー)」。

| キー | 動作 | 出典 |
|---|---|---|
| Alt+`（バッククォート） | 日本語入力のオン/オフ | S1, S2, S3 |
| Ctrl+CapsLock | 日本語キーボードの「ひらがな」キー相当 | S1, S2, S3 |
| Alt+CapsLock | 日本語キーボードの「Shift+ひらがな」キー相当（＝カタカナモード） | S1, S3。出典で食い違う: S1・S3 は Alt+CapsLock、S2 は「Shift+CapsLock」とし、S2 には Shift+CapsLock の行が 2 つある |
| Shift+CapsLock | 日本語キーボードの「英数」キー相当 | S1, S2, S3 |
| Ctrl+Space | S1 の表に無い。キーの割り当て（§4.2）での既定は「なし」 | S1, R3, HP |
| Win+Space | キーボードレイアウト（言語）の切り替え。IME 内部の機能ではない | S3 |

- US 配列で「無変換/変換」に相当する既定キーは資料に無い。
- Ctrl+Space を IME オン/オフにするには、キーの割り当てを変える（§4.2）。

### 1.5 実機で見た既定キーの動き

資料に無い既定キーを、新 MS-IME（Windows 11 10.0.26300、キーの割り当ては既定、US 配列 `kbd101`）で確かめた。

- **見方:** `tools/keyprobe/msime_tsf_table.py`。TSF の RichEdit（`SES_USECTF`）の窓に `SendInput` でキーを送り、
  アプリに届いた down（＝ IME が食べなかったキー）、キーの直後の文字、Esc を 3 回押したあとに残る文字（＝確定した文字）を記録する。
  9 つの状態 × 107 キー。状態の作り方は「kanji」を打つ（②）、Space を 1 回（③）、2 回（④）、「watashihanamaedesu」を変換して Shift+← （⑤）など。
- **IMM のアプリでは動きが違う。** 同じ表を IMM の窓（`target_imm.py`）でも採ると、963 件のうち 177 件で、食べるか通すかが違った
  （③〜⑤では IMM のアプリでほとんどのキーを食べる。②の Delete は IMM のアプリでは通る）。以下は TSF のアプリでの結果。
- 押し続けとキーの up は、メモ帳でも確かめた（`msime_notepad.py`、`msime_hold.py`）。
- 候補ウィンドウと下線（注目文節、未変換の文字）は、同じ窓でキーごとに画面を撮って見た（`msime_tsf_seq.py`）。
  新 MS-IME の候補ウィンドウは「Windows Input Experience」の全画面の窓に描かれるので、窓の一覧からは開いているか分からない。

状態の番号は §2 の旧 IME の表と同じ。「予測」は予測候補ウィンドウにフォーカスがある状態。

**アプリに通すキー**

「確定して通す」は、入力中の文字を全部確定してから、キーをアプリに渡す。「そのまま通す」は、確定せずにキーをアプリに渡す。
ここに無いキーは、②〜⑤と予測では食べる（§2 の表の働きをするか、何もしない）。①と確定の直後では、空白・文字・数字・CapsLock の和音（下の「モード」）を食べ、ほかは通す。

| キー | ② 入力のみ | ③ 変換済み | ④ 候補一覧 | ⑤ 文節長変更 | 予測 |
|---|---|---|---|---|---|
| F1、F3、F4、F11、F12、CapsLock、Shift+F6、Ctrl+F6、Ctrl+Tab、Ctrl+Home、Ctrl+End、Ctrl+PageUp、Ctrl+PageDown、Ctrl+`` ` `` | そのまま通す | そのまま通す | そのまま通す | そのまま通す | そのまま通す |
| F2 | そのまま通す | 食べる | 食べる | 食べる | そのまま通す |
| Insert、Shift+Delete、Shift+End、Shift+PageUp、Shift+PageDown、Ctrl+C、Ctrl+J、Ctrl+Q、Ctrl+R、Ctrl+V、Ctrl+W、Ctrl+Shift+Enter、Ctrl+Shift+矢印、Alt+矢印、Alt+Enter | 確定して通す | 確定して通す | 確定して通す | 確定して通す | 確定して通す |
| PageUp、PageDown | 確定して通す | 確定して通す | 食べる | 確定して通す | 食べる |
| Shift+↑、Shift+F10 | 確定して通す | 確定して通す | 食べる | 確定して通す | Shift+↑ は食べる、Shift+F10 は確定して通す |
| Shift+Home | 確定して通す | 食べる | 食べる | 食べる | 確定して通す |
| Ctrl+Backspace | 確定して通す | 食べる（文節戻し） | 食べる | 確定して通す | 確定して通す |
| Tab | 食べる | 確定して通す | 食べる | 確定して通す | 食べる |
| Delete、↑、↓、Ctrl+E、Ctrl+G、Ctrl+X | 食べる | 確定して通す | 食べる | 食べる | 食べる |
| → | 食べる | 文節が 1 つのとき確定して通す（先頭の文節にいるときは次の文節へ） | 食べる | 食べる | 食べる（確定する） |
| Ctrl+←、Ctrl+→、Ctrl+↑ | 食べる | 食べる | 食べる | そのまま通す | 食べる |
| Ctrl+A、Ctrl+F | 食べる | 食べる | 食べる | 確定して通す | 食べる |

- 「そのまま通す」のキーでアプリがカーソルを動かすと、入力中の文字が確定することがある（Ctrl+Home、Ctrl+PageUp が④と予測で確定した）。
- **Alt を押すと、入力中の文字を確定する。** Alt だけを押して離しても、Alt+Z のような割り当ての無い和音でも確定する。Alt キーとその和音はアプリに届く。
- ②の Ctrl+Backspace は、確定したあとアプリが単語を消す（入力中のカーソルが途中にあると、カーソルより前の単語を消す）。

**旧 IME の表（§2）と働きが違うキー**（ほかの、食べるキーの働きは §2 の表と同じだった。文字種の変換、Ctrl+K/L と Shift+←/→ の文節長、
Shift+↓ の 1 文字確定・先頭確定、Ctrl+↓・Ctrl+N の文節確定、Esc・Ctrl+Z の文節戻し（③）、Ctrl+Space・Ctrl+Shift+Space の空白など）

| キー | 状態 | 新 MS-IME | 旧の表 |
|---|---|---|---|
| Ctrl+Z | ② | 食べて何もしない | 全消去 |
| ↑、Ctrl+E | ② | 予測候補に入る | –、– |
| ↓、Ctrl+X | ② | 予測候補に入る | –、– |
| Ctrl+Backspace | ② | 確定して通す | 前字削除 |
| Delete、Ctrl+G | ③ | 確定して通す | 1文字削除 |
| Ctrl+Backspace | ① | 通す（確定の取り消しにならない） | 確定取消 |
| Shift+Enter | ②〜⑤ | 食べて何もしない | – |

**モード（US 配列のキー）**

| キー | ① 入力なし | ② 入力のみ・④ 候補一覧・⑤ | ③ 変換済み | オフ |
|---|---|---|---|---|
| Alt+`` ` `` | オフにする | 確定してオフにする | 確定してオフにする | オンにする（ひらがな） |
| Ctrl+CapsLock | ひらがなモード | ひらがなモード（入力中の文字は残す） | 同左 | オンにする（ひらがな） |
| Alt+CapsLock | カタカナモード | 確定してカタカナモード | 確定してカタカナモード | オンにする（カタカナ） |
| Shift+CapsLock | オフにする | 英数モード（入力中の文字は残し、続きを英字で入れる） | 確定してオフにする | オンにする（ひらがな） |

- TSF のアプリでは、Alt+`` ` `` の `VK_KANJI` は down も up もアプリに届く（切り替えはする）。Shift+CapsLock・Ctrl+CapsLock・Alt+CapsLock の down は届かない。Ctrl+`` ` `` は MS-IME が使わず、アプリに `VK_DBE_SBCSCHAR`（0xF3）・`VK_DBE_DBCSCHAR`（0xF4）として届く。
- **押し続けると、繰り返しのたびに実行する。** Alt+`` ` `` と Shift+CapsLock は、繰り返しのたびにオンとオフが入れ替わる（メモ帳で、down 16 回でオフ、17 回でオン）。
  Ctrl+CapsLock と Alt+CapsLock は、何回実行しても結果が同じ。
- **Alt を先に離したあとの繰り返しは、`` ` `` の入力になる**（オンなら入力中に「‘」、オフならアプリに「`` ` ``」。メモ帳でも同じ）。
  `` ` `` を先に押してから Alt を押したとき（[windows.md](windows.md) §3.2 の順 C・D）も、切り替えずに `` ` `` を入れる。
- 予測（フォーカスあり）での Shift+CapsLock は、③と同じく、確定してオフにする。
- 文字キーのすぐあとの Shift+CapsLock も②と同じ（ローマ字の途中の「ｋ」でも、文字を残して続きを英字で入れる）。

**そのほか**

| 項目 | 新 MS-IME |
|---|---|
| キーの up | 食べた down の up も、アプリに届く（TSF のアプリと IMM のアプリの両方） |
| 空白 | Space は入力モードの幅（ひらがなでは全角）。Shift+Space は別の幅 |

| ⑤の見え方 | 伸縮した文節は読みで出る。縮めて切り離した字は、1 つの文節になり、読みで出る（未変換の下線）。伸ばして隣の文節から字を取ると、隣の文節の残りが読みで出る。ほかの文節は変換したまま |
| ⑤の Space | 伸縮した文節と、読みで出ている隣の文節を変換して③に戻る。候補ウィンドウは出さない |
| ⑤を Space 以外で抜ける | → などで⑤を抜けても、読みの文節は読みのまま。Enter は読みのまま確定する。読みの文節に移って Space を押すと、③の 2 回目の Space と同じく、候補ウィンドウを開いて次の候補へ進む（見たのは、1 番目の候補が読みと同じ文字だったとき）。⑤の F7 は、注目文節をカタカナにする |
| 伸縮できない端 | 文節が 1 つのときや最後の文節で Shift+→、1 字の文節で Shift+← を押すと、文節は変わらない。③は③のまま、④は候補ウィンドウを閉じて③、⑤は⑤のまま |
| 予測候補 | 入力するとそのまま予測候補ウィンドウが出る（フォーカスは無い） |
| 変換済みで文字を打つ | 確定して、新しい入力を始める |

[KIRI]（2020 年、新 IME）も「文節を伸ばしたり縮めたりする操作は、Microsoft IME のデフォルトのキーアサインでは Shift+左右矢印」と書く。

## 2. 旧 IME の既定キー表（テンプレート「Microsoft IME」）

旧 IME の「キー設定」画面を転記した [R1] による（[R1] は Windows 10/11 の旧 IME で採ったと書く）。状態の列名と意味は [R2] と [S4] による。

**状態の列**

| 列名 | 意味 (R2) | S4 の英語名 |
|---|---|---|
| ① 入力/変換済み文字なし | 何もしていない状態 | No input/Converted strings |
| ② 入力文字のみ | 入力して、まだ変換していない状態 | Only Input strings |
| ③ 変換済み | 変換して、まだ確定していない状態 | Converted |
| ④ 候補一覧表示中 | 変換候補の一覧を表示している状態 | Showing Candidate List |
| ⑤ 文節長変更中 | 文節の区切りを変えている状態 | Changing POS boundary |
| ⑥ 変換済み文節内入力文字 | 変換中に文字を入力した、または再変換した状態 | Char Input into Converted POS |

- 「予測候補表示中」という独立した状態の列は無い。予測候補は②で Tab を押すと出る（「予測候補表示」）。
- 表の「–」は割り当てなし。旧 IME の「キー設定」の画面自体が空きのセルを「-」と表示し、そのセルを選ぶと説明欄が「Unassigned」になる（[SCREEN]）。
- §2.2 の ImeOn・ImeOff の 7 行は画面にあり、[R1] に無い（[SCREEN]）。

### 2.1 スペース・Enter・Esc・Backspace など

| キー | ①なし | ②入力のみ | ③変換済み | ④候補一覧 | ⑤文節長変更 | ⑥文節内入力 |
|---|---|---|---|---|---|---|
| Space | 空白 | 全変換 | 拡張候補 | 変換+次 | 文節変換 | 全変換 |
| Ctrl+Space | – | 半角空白 | 半角空白 | 半角空白 | 半角空白 | 半角空白 |
| Shift+Space | 別幅空白 | 全変換 | 前候補 | 前候補 | 文節変換 | 全変換 |
| Ctrl+Shift+Space | 全角空白 | 全角空白 | 全角空白 | 全角空白 | 全角空白 | 全角空白 |

- 使用状況データの収集: Microsoft へ送るかどうか [R3][MEMO]。

### 4.5 第三者の評価

- [AT2011][AT2111]: 新 IME ではキー設定がほとんどカスタマイズできない。アップデートでキー設定が既定に戻った。VJE や WX を使っていた人には「かなり使いにくい」。回避策は旧 IME に戻すか、Google 日本語入力に移ること。
- [KIRI]: 変換/無変換の割り当てが簡単になったのは利点。一方で、割り当てられるのは 4 キー × 2〜4 機能だけ。文節伸縮を Ctrl+I/O に移すといった細かい変更はできない。
- [R3]: 旧 IME の状態 × キーの表は「一目で理解しづらかった」。4 つに絞られて分かりやすくなった、と好意的。
- [MYNAVI]: 新 IME は変換時のキー割り当てが限られる。内部のバージョンは 15.0 のままで、変換エンジンは同じで見た目が変わっただけ「のようにも見える」。
