# 同時打鍵の状態機械（親指キーが複数ある配列）

JIS 106 では、親指が Space・無変換・変換のどれを押すかわからない。
この文書は、3 個の親指キーの押下と解放をすべて使って同時打鍵を判定する状態機械の仕様である。
親指キーはどのキーボードでもこの 3 個で、無変換・変換の無いキーボード（US）では Space だけが届く。そのときの動きは [CONVERSION.md](CONVERSION.md) §2 の Space だけの規則と同じになる（§10）。

実装は `yuragi/chord/fsm.py`（`ChordFsm`）。出したトークンをセッションと変換につなぐ規則は [JIS.md](JIS.md) §5 にある。

---

## 1. 前提

### 親指キー

| 親指キー | 押す親指 |
|---|---|
| `space` | 左右どちらも |
| `muhenkan`（無変換） | 左だけ |
| `henkan`（変換） | 右だけ |

無変換の左の Alt と、変換の右のカタカナひらがなローマ字は親指キーにしない。親指がそこまでかぶった打鍵は誤打とする。
修飾キー（Shift・Ctrl・Alt）を伴う親指キーは状態機械に入れず、キー表のコマンドにする。

### 打鍵のモデル

- **A1**: 同時打鍵 1 回は、文字キー 1 個と親指打鍵 1 回の組である。
- **A2**: 無変換には左親指しか届かず、変換には右親指しか届かない。
- **A3**: 同じ親指の打鍵どうしは時間的に重ならない。
- **A4**: 親指打鍵は短く、時間的に重なるのは隣の親指打鍵とだけである。
- **A5**: 1 回の親指打鍵は、複数の親指キーに触れることがある。複数の親指キーに触れる場合は、触れた親指キーをほぼ同時に押し、ほぼ同時に離す。

A3 から、時間的に重なった 2 つの親指打鍵は左右が違う。
A4 は、Space が押されたままのとき「押しているのは直前の親指打鍵である」と読むための仮定で、ANSI の左右交互と同じ仮定である。

### 見えない親指打鍵

Space が押されている間に反対の親指が Space を打っても、信号は出ない。これを見えない親指打鍵と呼ぶ。

- 見えない親指打鍵は、使用済みの Space が押されている間にだけ起こる。
  Space が上がっていれば、親指打鍵は必ずどれかの親指キーの down として見える。
- 無変換と変換の両方が押されている間は、空いている親指がないので、見えない親指打鍵も起こらない。

### 証拠の 2 種類

| 種類 | 内容 | 運び方 |
|---|---|---|
| 確定 | 無変換・変換を押した。または、反対の親指が無変換・変換を押している間に打った | 打鍵ごとの `struck`・`held`・`over`（§8） |
| 交互 | 1 回の Space の押下の中で続いた親指打鍵 | `press`・`turn`（§8） |

交互は Space でだけ使う。無変換・変換が関わる重なりは、すべて確定として打鍵ごとに表せるからである。

## 2. 入力

どの入力も時刻 `t`（ms）を持つ。

| 入力 | 意味 |
|---|---|
| `M↓(k)` `M↑(k)` | 文字キー `k` の押下と解放 |
| `O↓(x)` `O↑(x)` | 親指キー `x` の押下と解放 |
| 期限 | `t` が `deadline` 以上になった |
| `reset` | リテラルや編集の境目で、セッションが判定を閉じる。キーは押されたままでありうる |
| `clear` | フォーカスの喪失など。以後、押されていたキーの解放は届かない |

押されている親指キーの `O↓(x)` と、押されていない親指キーの `O↑(x)` は無視する。

---

## 3. 定数

| 定数 | 値 | 意味 |
|---|---|---|
| `TIMEOUT_MS`（T） | 80 ms | 判定の窓 |
| `OVERLAP_MS`（V） | 20 ms | 短い重なりの上限 |
| `JOIN_MS`（J） | 30 ms | 1 回の親指打鍵が 2 個目のキーを押すまでのずれの上限 |

J は見積もりの初期値で、実機で合わなければ変える。J の判定は `O↓` が届いた時点の時刻の比較で行い、専用のタイマーは持たない。

## 4. 内部の値

| 値 | 内容 |
|---|---|
| `state` | S1〜S7（§5） |
| `held` | 押されている親指キーと、その down の時刻 |
| `stroke` | 最後に始まった親指打鍵（下の表）。なければなし |
| `carrier` | 使用済みで押されたままの Space の使い道。なし・`chord`・`tap` |
| `m` `m_time` `m_held` | 保留中の文字キー、その down の時刻、そのとき押されていた親指キーの集合 |
| `m_under` `m_from` `m_to` | 保留中の文字が重なったつなぎの使い道（なし・`chord`・`tap`）、重なりの始まりと終わりの時刻 |
| `press` `turn` | 押下の通し番号と、その押下で出した同時打鍵の数 |
| `deadline` | 期限。なければ期限の入力は起きない |
| `pressed_at` `last_length` | 押されている文字キーの down の時刻と、最後に離れた文字キーの押下の長さ |

`stroke` の中身:

| 値 | 内容 |
|---|---|
| `keys` | この親指打鍵に属する親指キー。押された順。J 以内に押された一組である |
| `start` | 最初のキーの down の時刻 |
| `before` | `start` の直前に押されていた親指キーの集合（ほかの親指打鍵のキー） |
| `linked` | `start` の時点で `carrier` が `chord` だったら真 |
| `first` | 単独打鍵になったときに働くキー。ふつうは `keys[0]`。未使用の親指打鍵を引き継いだときは、引き継ぐ前の `first` |
| `over` | 直前の同時打鍵の親指打鍵が押されている間に押された、Space 以外のキー（`linked` が真のときの `keys`。引き継いだ分を含む） |
| `use` | `fresh`（未使用）・`chord`（同時打鍵に使った）・`tap`（単独打鍵にした）・`void`（`reset` で捨てた） |
| `ended` | どれかのキーが離れたら真 |
| `token` | 出した同時打鍵の `press` と `turn`。`use` が `chord` で、`reset` をまたいでいないときだけ持つ |

言葉の定義:

- **未使用の親指打鍵がある**: `stroke.use` が `fresh`。
- **つなぎがある**: `carrier` がなしでない。このとき Space は `held` にある。
- **左右が合う**: `stroke.keys` に `x` を加えても、無変換と変換の両方を含まない。
- **追加できる**: `stroke.use` が `chord` か `void` で、`stroke.ended` が偽で、`t − stroke.start ≦ J` で、`x` と左右が合う。
- **重なり `c(t)`**: 保留中の文字とつなぎの Space が、時刻 `t` までに同時に押されていた長さ。`min(t, m_to) − m_from`（`m_to` がなしなら `t − m_from`）。
- **親指が空いていない**: `m_held` が無変換と変換の両方を含む。

## 5. 状態

| 状態 | 未使用の親指打鍵 | つなぎ | 保留中の文字 |
|---|---|---|---|
| S1 | ない | ない | ない |
| S2 | ない | ない | ある |
| S3 | ある | どちらでも | ない |
| S4 | ある | どちらでも | ある。文字が親指打鍵より先 |
| S5 | ある | どちらでも | ある。親指打鍵が文字より先 |
| S6 | ない | ある | ない |
| S7 | ない | ある | ある |

- 使用済みの無変換・変換だけが押されている状況は S1・S2 である。そこから見えない親指打鍵は起こせない（§1）。
  無変換と変換だけで打つ利用者は、S6・S7 を通らない。
- S3〜S5 でつなぎがあるのは、Space を押したまま別の親指キーで次の親指打鍵を始めたときである。

**戻り先**: 未使用の親指打鍵がなくなったあとの状態。
つなぎがあれば S6（文字が保留なら S7）、なければ S1（文字が保留なら S2）。S1・S2 に戻るときは `m_under` をなしにする。

**期限**:

| 状態 | `deadline` |
|---|---|
| S1・S6 | なし |
| S2・S5・S7 | `m_time + T` |
| S3・S4 | `stroke.start + T` |

## 6. 手続き

遷移表（§7）はこの手続きを使う。

### 文字を保留にする（`k`、時刻 `t`）

1. `m = k`、`m_time = t`、`m_held =` 押されている親指キーの集合、とする。
2. `m_under = carrier`、`m_from = t`、`m_to =` なし、とする。

### 新しい親指打鍵を始める（`x`、時刻 `t`）

`stroke` を次の値に置き換える。

- `keys = (x)`、`start = t`、`use = fresh`、`ended = 偽`、`token =` なし。
- `before =` `x` を入れる前の `held` のキーの集合。
- `linked =`（`carrier` が `chord`）。
- `first = x`、`over =` 空。そのあと「キーを加える」の 2 を `x` について行う。

### 未使用の親指打鍵を引き継ぐ（`x`、時刻 `t`）

文字と組まないまま、別の親指打鍵が始まったときに使う。

1. 今の `stroke.first` と `stroke.over` を覚える。
2. 新しい親指打鍵を始める。
3. `first` と `over` を、覚えた値と新しい値をつないだものにする（`first` は覚えた値、`over` は覚えた値に新しい分を足す）。

前の親指打鍵のキーは、押されていれば新しい `before` に入る。前の親指打鍵は単独打鍵にしない。
文字が来ないまま終われば、まとめて最初のキーの機能が 1 回だけ働く。

### キーを加える（`x`）

1. `stroke.keys` に `x` を加える。
2. `stroke.linked` が真で `x` が Space でなければ、`stroke.over` に `x` を加える。

### 同時打鍵を出す（`stroke` を使う）

1. `stroke.linked` が偽なら、`press` を 1 増やし、`turn` を 0 にする。
2. `turn` を 1 増やす。
3. `AmbShift(m, struck = stroke.keys, held = stroke.before, press, turn)` を出す。
4. `stroke.use` を `chord` に、`stroke.token` を `(press, turn)` にする。
5. `stroke.keys` に Space があり、まだ押されていれば、`carrier` を `chord` にする。
6. `m` をなしにする。

### 見えない同時打鍵を出す

1. `turn` を 1 増やす。
2. `AmbShift(m, struck = (), held = m_held, press, turn)` を出す。
3. `m` をなしにする。

### 単独を出す

`Plain(m)` を出し、`m` をなしにする。

### 単独打鍵を出す（`stroke` を使う）

1. `turn` が 1 以上なら、`stroke.over` のキー `k` ごとに `ThumbOver(press, turn, k)` を出す。
   直前の同時打鍵の親指打鍵が押されている間に、この親指打鍵が始まったという証拠である。
2. `ThumbTap(stroke.first)` を出す。最初に押されたキーの機能を 1 回だけ働かせる。
3. `stroke.use` を `tap` にする。
4. `stroke.keys` に Space があり、まだ押されていれば、`carrier` を `tap` にする。文字が保留中なら `m_under = tap`、`m_from = m_time`、`m_to =` なし、とする。
5. `press` を 1 増やし、`turn` を 0 にする。単独打鍵は交互を切る。

### 追従の判定（時刻 `t`）

使用済みの Space が押されている間に打った文字を、見えない同時打鍵か単独かに決める。

1. `m_under` が `tap` なら、単独を出す。
2. 親指が空いていなければ、単独を出す。
3. `last = last_length`（まだなければ T）とする。
4. `c(t) ≧ last − c(t)` なら見えない同時打鍵を出す。そうでなければ単独を出す。

### 押したまま決まる追従

1. `m_under` が `tap` なら、単独を出す。
2. 親指が空いていなければ、単独を出す。
3. そうでなければ、見えない同時打鍵を出す。

### 組まなかった文字を決める（時刻 `t`、きっかけ）

未使用の親指打鍵と組まなかった保留中の文字を決める。

1. `m_under` がなしなら、単独を出す。
2. きっかけが文字の解放で、`m_to` がなし（つなぎがまだ続いている）なら、押したまま決まる追従を行う。
3. そうでなければ、追従の判定を行う。

ANSI では未使用の親指打鍵とつなぎが同時にあることがないので、いつも 1 になる。

## 7. 遷移

各表は「入力が届いたときの状態」ごとに、上から順に行うことを書く。
表にない組み合わせでは何もしない。どの遷移のあとも、`deadline` は §5 の表に従って置き直す。

### 7.1 `O↓(x)`

§2 の前処理を通った、押されていないキーの押下である。次の表の上から最初に当てはまる行を行い、最後に `held` に `x` と `t` を入れる。

| 条件 | 行うこと | 次の状態 |
|---|---|---|
| S3・S4・S5 で左右が合い、`t − stroke.start ≦ J` | キーを加える | 変わらない |
| S3 でそれ以外 | 未使用の親指打鍵を引き継ぐ | S3 |
| S4 でそれ以外 | 同時打鍵を出す。新しい親指打鍵を始める | S3 |
| S5 でそれ以外、`t1 > t2` | 未使用の親指打鍵を引き継ぐ | S4 |
| S5 でそれ以外、`t1 ≦ t2` | 同時打鍵を出す。新しい親指打鍵を始める | S3 |
| S1・S2・S6・S7 で追加できる | 下の「遅れたキーを加える」を行う | 下に書く |
| S1・S6 | 新しい親指打鍵を始める | S3 |
| S2・S7 | 新しい親指打鍵を始める | S4 |

S5 では `t1 = m_time − stroke.start`、`t2 = t − m_time`。保留中の文字は、down が近いほうの親指打鍵と組む。

**遅れたキーを加える**:

1. `stroke.keys` に `x` を加える。
2. `stroke.token` があれば `ThumbJoin(stroke.token, x)` を出す。
3. 文字が保留中なら、`m_held` に `x` を加える。
4. `x` が Space で `stroke.use` が `chord` なら、`carrier` を `chord` にする。文字が保留中なら `m_under = chord`、`m_from = t` とする。状態は S1→S6、S2→S7。
5. それ以外は、状態は変わらない。

行の理由:

- J を超えて押されたキー（A5）と、左右が合わないキー（A2）は、別の親指の打鍵である。前の親指打鍵には加えない。
  加えると、前の親指打鍵のキーが次の文字の `struck` に入り、逆向きの左右が確定する。
- S3 で別の親指打鍵が始まったら、前の親指打鍵は文字と組まずに終わる。単独打鍵にはせず、新しい親指打鍵に引き継ぐ。
  前の親指打鍵が押したままのキーは新しい `before` に入るので、次の同時打鍵は「反対の親指がふさがっている」証拠を持つ。
  ANSI でも、文字と組み損ねた Space の押下は、押されたまま次の文字の同時打鍵に使われる。それと同じ扱いである。
- S4（文字、親指打鍵の順）で別の親指打鍵が始まったら、保留中の文字は前の親指打鍵と組む。新しいキーは次の文字のための打鍵である。
- S5（親指打鍵、文字の順）で別の親指打鍵が始まったら、文字は down が近いほうと組む。S4 の 3 キーの判定と同じ形である。
- S7 から S4 に移った文字は、つなぎとの重なりを持ったままである。新しい親指打鍵と組まなければ「組まなかった文字を決める」で扱う。

### 7.2 `O↑(x)`

最初に共通の処理を行う。

1. `held` から `x` を除く。
2. `x` が `stroke.keys` にあり、`stroke.ended` が偽なら、`stroke.ended` を真にする。このとき `stroke.use` が `fresh` だったなら「親指打鍵の終わり」を行い、そこで終える。
3. `x` が Space で、つなぎがあれば「つなぎの Space の解放」を行う。
4. どちらでもなければ、状態は変わらない（使用済みの無変換・変換、終わった親指打鍵の残りのキー、引き継がれた親指打鍵のキー）。

親指打鍵の終わりは、その親指打鍵のキーが最初に 1 個離れた時点である。

**親指打鍵の終わり**（S3・S4・S5）:

| 状態 | 条件 | 行うこと | 次の状態 |
|---|---|---|---|
| S3 | | 単独打鍵を出す | 戻り先 |
| S4 | | 同時打鍵を出す | 戻り先 |
| S5 | `t1 > t2` かつ `t2 < V` | 単独打鍵を出す。文字は保留のまま | 戻り先（文字が保留） |
| S5 | それ以外 | 同時打鍵を出す | 戻り先 |

S5 では `t1 = m_time − stroke.start`、`t2 = t − m_time`。

**つなぎの Space の解放**:

| 状態 | 条件 | 行うこと | 次の状態 |
|---|---|---|---|
| S3 | | `carrier` をなしにする | S3 |
| S4・S5 | | `carrier` をなしにする。`m_under` がなしでなければ `m_to = t` とする | 変わらない |
| S6 | | `carrier` をなしにする | S1 |
| S7 | `m_under` が `tap`、または `c(t) < V` | `carrier` をなしにする。`m_under` をなしにする。文字は保留のまま | S2 |
| S7 | それ以外 | 追従の判定を行う。`carrier` をなしにする | S1 |

### 7.3 `M↓(k)`

最初に `pressed_at` に `k` と `t` を入れる。

| 状態 | 条件 | 行うこと | 次の状態 |
|---|---|---|---|
| S1 | | `k` を保留にする | S2 |
| S2 | | 単独を出す。`k` を保留にする | S2 |
| S3 | | `k` を保留にする | S5 |
| S4 | `t1 ≦ t2` | 同時打鍵を出す。`k` を保留にする | 戻り先（S7 か S2） |
| S4 | `t1 > t2` | 組まなかった文字を決める。`k` を保留にする | S5 |
| S5 | | 同時打鍵を出す。`k` を保留にする | 戻り先（S7 か S2） |
| S6 | | `k` を保留にする | S7 |
| S7 | | 追従の判定を行う。`k` を保留にする | S7 |

S4 では `t1 = stroke.start − m_time`、`t2 = t − stroke.start`。同じなら前の文字と組む（NICOLA 規格書 5.4.2）。

### 7.4 `M↑(k)`

`k` が保留中の文字 `m` なら、次の表を行う。

| 状態 | 条件 | 行うこと | 次の状態 |
|---|---|---|---|
| S2 | | 単独を出す | S1 |
| S4 | `t1 > t2` かつ `t2 < V` | 組まなかった文字を決める（きっかけは文字の解放） | S3 |
| S4 | それ以外 | 同時打鍵を出す | 戻り先 |
| S5 | | 同時打鍵を出す | 戻り先 |
| S7 | | 押したまま決まる追従を行う | S6 |

S4 では `t1 = stroke.start − m_time`、`t2 = t − stroke.start`。同じなら同時打鍵（規格書 5.5.2 の n = 1）。

表のあと、`k` が保留中かどうかによらず、`last_length = t − pressed_at[k]` として `pressed_at` から `k` を除く。

### 7.5 期限

| 状態 | 行うこと | 次の状態 |
|---|---|---|
| S2 | 単独を出す | S1 |
| S3 | 単独打鍵を出す | 戻り先 |
| S4・S5 | 同時打鍵を出す | 戻り先 |
| S7 | 押したまま決まる追従を行う | S6 |

S3 の期限で Space を含む親指打鍵が単独打鍵になると、`carrier` が `tap` になり S6 に移る。
その Space が押されている間に打った文字は単独になる。

### 7.6 `reset` と `clear`

`reset`:

- `m`、`carrier`、`deadline` をなしにする。
- `stroke.use` が `fresh` なら `void` にする。`stroke.token` をなしにする。
  遅れたキーは 30 ms の間この親指打鍵に加わるが、`ThumbJoin` は出さない。
- `press` を 1 増やし、`turn` を 0 にする。
- `held` は残す。押されているキーは物理的な事実で、以後の `before` と `m_held` に使う。
- 次の状態は S1。押されたままだった Space はつなぎにならない。

`clear`:

- `reset` に加えて、`held`、`stroke`、`pressed_at` を空にする。解放が届かないキーを押されたままにしない。

## 8. トークン

| トークン | 意味 |
|---|---|
| `Plain(key)` | 文字キー単独 |
| `AmbShift(key, struck, held, press, turn)` | 文字キーと親指打鍵 1 回の同時打鍵 |
| `ThumbTap(key)` | 親指キー単独。`key` は `space`・`muhenkan`・`henkan`。そのキーの機能をキー表から引く |
| `ThumbJoin(press, turn, key)` | 出力済みの `AmbShift` の `struck` に、遅れて押されたキーを足す |
| `ThumbOver(press, turn, key)` | 出力済みの `AmbShift` の `over` に、あとから重なった単独打鍵のキーを足す |

`AmbShift` の証拠:

| 項目 | 内容 |
|---|---|
| `struck` | この親指打鍵が押した親指キー。押された順。空なら見えない親指打鍵 |
| `held` | 親指打鍵の始まり（見えない場合は文字の down）に、ほかの親指打鍵が押したままだった親指キー |
| `over` | この親指打鍵が押されている間に、単独打鍵として押された無変換・変換。`ThumbOver` で足す。初めは空 |
| `press` | Space の押下の通し番号。つなぎの Space が押されている間に続いた同時打鍵が同じ番号になる |
| `turn` | その押下で何番目の同時打鍵か（1、2、…） |

`press` が変わるのは、つなぎの Space なしで始まった親指打鍵が同時打鍵になったとき、単独打鍵のとき、`reset` のときである。
無変換・変換だけが押されたままでも、`press` はつながらない。

状態機械は左右を判定しない。証拠だけを渡す。

- 単独か同時かの判定は 1 回だけで、出した `Plain`・`AmbShift`・`ThumbTap` の種類と順序は変えない。
- `ThumbJoin` と `ThumbOver` は証拠を足すだけである。セッションは、未確定のトークン列に対象の `AmbShift` が残っていれば足し、なければ捨てる。
- `ThumbOver` は、同じ入力で出る `ThumbTap` より前に出す。変換の操作より先に証拠が入る。

## 9. 証拠の使い方（変換側）

### 確定する左右

`to_lattice_token` が `struck`・`held`・`over` から導く。

| 証拠 | 左右 | 根拠 |
|---|---|---|
| `struck` に無変換がある | 左 | A2 |
| `struck` に変換がある | 右 | A2 |
| `held` か `over` に変換がある | 左 | A3（右親指はふさがっている） |
| `held` か `over` に無変換がある | 右 | A3 |

- 左と右のどちらか一方だけが出たら、その打鍵の `faces` をその側の面だけにする。
- 両方が出たら（誤打）、またはどちらも出なければ、両方の面を残す。
- 確定した側の面が空欄なら、その打鍵は何も入力しない。

### 交互

同じ `press` の同時打鍵は、`turn` の順に左右が交互である。
つなぎの Space が押されたまま次の親指打鍵が始まったなら、直前の親指打鍵がまだ Space を押している（A4）ので、2 つは時間的に重なっている（A3）。

`alternation.py` の規則がそのまま使える。

- 面が片側だけの打鍵は、その押下の向きを決める。確定した左右はこの形で押下の全体に伝わる。
- どちらの向きでも綴れない押下は拘束しない。確定した左右と交互が矛盾した場合（A4 に反する長押し）もここに入り、各打鍵は絞り込んだ後の面から自分で選ぶ。

## 10. Space だけのとき

親指キーが Space だけ（US）なら、次のことが成り立ち、この仕様は CONVERSION.md §2 の Space だけの規則と同じ `Plain`・`AmbShift`・`ThumbTap` の列を出す。

- 親指打鍵のキーは 1 個で、追加は起きない。`ThumbJoin` も `ThumbOver` も出ない。
- `O↓(space)` が届くのは Space が上がっているときだけで、そのときつなぎはない。S6・S7 から S3・S4 への遷移は起きない。
- 未使用の親指打鍵とつなぎが同時にあることはない。「組まなかった文字を決める」はいつも単独を出す。
- `struck` は `(space)` か空、`held` は空か `{space}` で、確定する左右は出ない。
- 同じ `press` にまとまる同時打鍵の組と `turn` は、Space だけの規則と同じである。

時刻は ms。「右」「左」は実際に打った親指で、状態機械には見えない。

## 12. 限界

- **ずれが J を超えた 1 回の親指打鍵（S4・S5 と、確定後）**: 2 個目のキーが新しい親指打鍵になる。
  文字が続けば、その文字に逆向きの左右が確定する。文字が続かなければ、2 個目のキーの単独打鍵が働き、前の同時打鍵にも逆向きの左右が確定する。
- **文字なしで親指キーを 2 個続けて押す（S3）**: 先のキーを離す前に次のキーを押すと、働くのは最初のキーの機能 1 回だけである。
  2 個を別々の単独打鍵にするには、先のキーを離すか、80 ms 待ってから次を押す。
- **引き継がれた Space**: 文字と組まないまま引き継がれた Space は、押されたままでもつなぎにならない。その間の見えない親指打鍵は単独になる。
- **単独か同時かの取り違え**: 文字が短く離れたときの逐次打鍵の判定（規格書 5.5.2）は ANSI と同じで、取り違えも同じだけ起きる。
  取り違えた打鍵の証拠は、取り違えた読みと矛盾しない形で付く。
- **A4 に反する長押し**: 片方の親指が Space を押したまま、もう片方が 2 回続けて打つと、交互の向きを誤る。ANSI と同じである。
  無変換・変換の証拠と矛盾した押下は拘束を外すので、その押下のほかの打鍵も交互の情報を失う。
- **解放の時刻**: Space と無変換・変換が同時に離れたかどうかは、左右の証拠にしない。A4 のもとでは確定と交互から導けることしか言わず、新しい情報がない。
- **「押さなかった」こと**: 変換に触れなかった Space だけの打鍵が左である見込みは使わない。利用者ごとの率が要るので、精度を測ってから検討する。

## 13. 検証

次の 2 つを `tests/test_thumb_keys.py` で確認する。乱数の種は固定で、列の数は環境変数 `YURAGI_FSM_RUNS` で変える（既定は 2000。実装時に各 10 万列で通した）。

| 確認 | 方法 |
|---|---|
| 証拠の正しさ | A1〜A5 と「ずれは 25 ms 以内」に従う親指打鍵を乱数で作り、実際の親指を知ったうえで、確定した左右と交互を照合する。逆向きの確定がないこと、交互の誤りがないこと、単独打鍵の数が実際と一致することを見る。Space だけを押す割合は 100%・80%・50%・0% |
| 状態の整合 | 親指キー 3 個と文字 3 個の任意の打鍵列（`reset`・`clear` を含む）で、§5 の表と内部の値が合うこと、全部離せば S1 に戻ること、`ThumbJoin`・`ThumbOver` の宛先があることを確かめる |

1 つ目の確認は、モデルに従う打鍵についてのものである。ずれを 60 ms まで広げると、逆向きの確定が出る（§12 の最初の項目）。試験はこれが出ることも確かめる。
§11 の例と、`clear` の個別の場合も同じファイルにある。実際の打鍵がモデルに合うか（J の値、A4）は、JIS の実機で測るまでわからない。
